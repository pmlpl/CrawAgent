## 〇、价值

- **改动前**：① 工作文件夹提示条里图标与路径间距小、上下视觉错位；切换项目只能点「选择项目」重新弹原生选框，之前用过的项目要重新选一遍路径。② `download_social_media` 下载视频时只有 `with_progress` 自动心跳"运行中… 已耗时 Xs"，没有下载百分比/速度——会话 372fa1d 实测：B 站视频几十 MB 下载几分钟，用户以为卡死。
- **改动后**：① 提示条右侧加向上箭头按钮，点击弹出历史项目菜单（最近用过的 work_dir 一键切换 +「打开新项目」+「清除项目」）；图标与路径间距/对齐修好。② 下载过程实时显示"下载 视频名 45% 12.3/27.1MB 2.1MB/s"进度行，用户始终知道在干什么。

## 一、背景与问题

1. workdir-bar（ChatPage.vue:155-160）CSS 已有 `gap:7px` + `align-items:center`，但 SVG 图标 `inline` 默认 `vertical-align:baseline` 与文字行高错位；间距视觉不够。指挥官实测反馈"文件夹 logo 和路径之间加一点间距，然后上下对齐"。
2. 切换项目：当前只有 ChatComposer 的「选择项目」按钮弹原生框重新选；meta.db `session_titles` 表里多个会话的 work_dir 没有快捷重选入口——指挥官要"右边加向上箭头，点击切换其他项目（之前打开过的历史项目）或打开新项目"。
3. `download_social_media` 用 `_download_to_file`（social_utils.py:114）`requests stream=True + iter_content(8192)` 下载，**没接 `report_progress`**；只有 `with_progress` 自动心跳（4s 阈值后每 5s 一条"运行中… 已耗时 Xs"）。指挥官实测反馈"在下载资料内容的话应该有一个动态下载进度条让用户知道在干什么"。
4. `_download_to_file` 是共用函数——`download_images` 等也可能调用（实施时 `grep _download_to_file` 全量清点），进度改造要兼顾所有调用方。

## 二、目标

1. workdir-bar：图标与路径间距加大、上下对齐（CSS）；右侧加**向上箭头按钮**，点击弹出历史项目菜单。
2. 历史项目菜单：最近 N 个用过的 work_dir（点击 = 绑定当前会话到该路径）+ 分隔线 +「打开新项目」（调 pick-folder）+「清除项目」（解绑）。
3. 历史项目查询端点：`GET /api/sessions/work-dirs/history` → 返回去重 + 按最近使用排序的 work_dir 列表。
4. `download_social_media` 下载进度：`_download_to_file` 加 Content-Length 进度统计 → `report_progress` 实时推送百分比/已下载/总大小/速度。
5. **不做**：下载完成后的文件预览；历史项目列表的编辑/删除；多文件并发下载（保持顺序）；进度条 UI 组件（用文本进度行走现成 trace 心跳通道，与 032 步进里程碑同链路，前端零改动）。

## 三、方案设计

### 3.1 workdir-bar CSS + 向上箭头菜单（ChatPage.vue）

- CSS：`gap:7px→10px`；SVG 加 `flex-shrink:0` + `display:block`（或固定 `line-height`）保垂直居中；调整 `padding`。
- 提示条右侧加向上箭头按钮（chevron-up SVG，与提示条同色系）：点击弹出绝对定位 dropdown 菜单。
- 菜单内容：
  - 历史项目列表（最近 10 个 work_dir，每项显示路径超长省略 + hover 全文，点击 → `POST /api/sessions/{current}/work-dir` 绑定该路径 → 头部提示条更新）
  - 分隔线
  -「打开新项目」（点击 → 调 useChat.chooseProject()，即 pick-folder + 绑定）
  -「清除项目」（点击 → `POST work-dir` 空 → 提示条消失）
- 菜单实现：简单绝对定位 dropdown（复用项目现有 dropdown 模式，不引新组件库）；点击外部关闭。

### 3.2 历史项目查询端点（后端）

- `GET /api/sessions/work-dirs/history`：`SELECT work_dir, MAX(rowid) AS last FROM session_titles WHERE work_dir != '' GROUP BY work_dir ORDER BY last DESC LIMIT 10`。
- 返回 `{work_dirs: ["path1", "path2", ...]}`，去重 + 按最近使用排序。
- 放 sessions 路由（与 work_dir.py 同包）。

### 3.3 下载进度条（social_utils._download_to_file）

- `_download_to_file` 加进度统计：
  - 取 `Content-Length` 头（无则只显示已下载字节，不显示百分比）；
  - `iter_content` 累计已下载字节，每 0.5s（或每 64KB）调 `report_progress(f"下载 {path.name} {pct}% {done_MB}/{total_MB}MB {speed}MB/s")`；
  - 速度计算：自上次上报以来的字节增量 / 时间增量。
- `download_social_media` 的 `save()` 函数透传文件名给 `_download_to_file`（path 已含 name，进度提示用 `path.name`）。
- 进度行走 `report_progress`（轨迹行）走现成 progress 心跳通道 → turn_engine WS → 前端 trace 卡片内联显示（与 032 步进里程碑同链路），**前端零改动**。
- 调用方清点：`grep _download_to_file crawagent/tools/` 全量确认（download_images 等如果调用同样受益）。

### 3.4 测试

- 后端：历史项目查询端点（去重/排序/空/limit）；`_download_to_file` 进度上报（mock requests stream + Content-Length + report_progress 断言调用次数与消息格式）；无 Content-Length 分支。
- 前端：workdir-bar 按钮渲染 + 菜单弹出 + 历史项点击绑定 + 打开新项目 + 清除 + 点击外部关闭。
- 基线：721 pytest + 68 vitest 起算同步计数。

### 怎么做到的（人话版）

两块独立改动，一批落地：

1. **workdir-bar 提示条 UX + 历史项目切换**：提示条图标加 `.wd-ico`（`display:block` + `flex:none`）消除 inline SVG 的 baseline 错位，`gap` 7→10px、padding 微调；右侧加向上箭头按钮（chevron-up），点击弹绝对定位 dropdown 菜单——历史项目列表（每项路径超长省略 + hover 全文）+ 分隔线 +「打开新项目」+「清除项目」。点击外部关闭用 document 级 click 监听 + `wdBarRef.contains(target)` 判定（onMounted 挂 / onUnmounted 卸）。菜单打开前调 `fetchWorkDirHistory()` 拉历史。
   - 后端历史查询：`GET /api/sessions/work-dirs/history` 委托 `meta_store.list_work_dir_history()`——`SELECT work_dir, MAX(work_dir_ts) ... GROUP BY work_dir ORDER BY last DESC LIMIT 10`，去重 + 按最近绑定时间倒序。
   - 前端动作收敛：把 035 `chooseProject` 里的 POST 段抽成 `bindWorkDir(path)`（单一真源），菜单的「历史项绑定」「清除项目」与「选择项目」的落库步骤全复用它；`clearWorkDir()` = `bindWorkDir('')`。

2. **下载进度条**：`_download_to_file`（social_utils，5 处调用方共用：bilibili_tool ×4、social_tool ×1）取 `Content-Length` 头，`iter_content` 累计已下载字节，每 0.5s（`_PROGRESS_REPORT_INTERVAL`）调 `report_progress` 推一行——有总大小时 `下载 clip.mp4 47% 13.0/27.1MB 6.0MB/s`，无 Content-Length 时 `下载 clip.mp4 已下载 5.0MB 2.1MB/s`。速度 = 自上次上报以来的字节增量 / 时间增量。下载结束补一行 `下载 clip.mp4 完成 100% 27.1MB 平均 2.8MB/s` 收尾。进度行走现成 `report_progress` → server 心跳 → `pushProgress` 链路（与 032 步进里程碑同通道），前端零改动——`pushProgress` 已过滤「运行中… 已耗时」心跳行，真实里程碑（含「下载 …」）原样进轨迹卡片 + typing pill。

### 说明（与规格偏差）

- **work_dir_ts 列替代 MAX(rowid)**：规格 §3.2 提议 `MAX(rowid)` 排序，但 `set_work_dir` 用 `INSERT ... ON CONFLICT DO UPDATE`——conflict-update 不改 rowid，导致「同会话换项目」后新绑的 path 仍挂老 rowid，排不到第一（与「最近使用」语义相悖）。改为新增 `work_dir_ts TEXT` 列（`_migrate_meta_columns` 自动迁移，老库连上即补），每次 set_work_dir 刷 ISO 时间戳，按 `MAX(work_dir_ts) DESC` 排序。test_work_dir_history_rebind_bubbles_to_top 专测此场景。历史查询逻辑抽到 `meta_store.list_work_dir_history()`（离线可测，不依赖 FastAPI）。
- **_fmt_progress / _fmt_progress_done 提取为纯函数 + _PROGRESS_REPORT_INTERVAL 常量**：规格内联描述格式，实现抽成两个纯 helper（无 mock 即可单测格式）+ 模块常量（测试 monkeypatch 到 0 强制每 chunk 上报，验证调用次数与消息）。
- **补「下载完成」行**：规格未明确要求，但避免最后一行停在 98% 然后消失的突兀感；`_fmt_progress_done` 含 100% + 平均速度。
- **chooseProject 复用 bindWorkDir**：规格前端小节只列新增函数，未要求重构；实现把 POST work-dir 段抽成 `bindWorkDir(path)` 单一真源（菜单历史项 / 清除 / 选择项目三路复用），减少重复。
- **调用方零改动**：`_download_to_file` 签名不变 `(url, path, headers) -> Path`，bilibili_tool / social_tool / download_images 的 5 处调用自动获得进度上报，social_tool.py 未动（规格「若需要」的判断 = 不需要）。
- 本变更已随本 commit 入库（代码与文档同批）。

### 缺陷修复（2026-10-01，指挥官真机报障）

**现象**：会话 372fa1d32874 把工作文件夹从 test 换绑到其他项目后，「切换项目」菜单里 test 消失——绑过的 3 个项目只显示 2 个，只能重新「打开新项目」再选一遍才能找回。

**根因**：历史列表数据源是 `session_titles.work_dir`——那是「各会话当前绑定」的快照。每个会话只有一行（thread_id 主键），换绑即覆盖旧值；旧路径若无其他会话恰好也绑过，就从库里彻底蒸发。§八 的 work_dir_ts 方案只解决了「同会话换项目排不到第一」的排序问题，没解决「快照 ≠ 历史」的语义问题。

**修复**：新增 append-only 绑定历史表 `work_dir_history(path, last_used)`——

- `set_work_dir` 非空绑定时 upsert 历史表；清除绑定（空串）不动历史——清除 ≠ 没打开过，像「最近文件」列表；
- `list_work_dir_history` 改查历史表 `ORDER BY last_used DESC LIMIT 10`；
- 老库回填：连接初始化迁移时把 `session_titles` 现存绑定快照 `INSERT OR IGNORE` 灌入（已被覆盖的路径无法追溯，属既成事实）；
- 前端零改动（消费的接口与字段不变）。

**测试**：test_work_dir.py 34 passed（新增 survives_rebind / survives_clear / backfill_from_legacy 3 用例）；全量 738 passed。旧用例 rebind_bubbles_to_top 的断言 `"/old" not in history` 恰是缺陷行为的钉子，删除并以 survives_rebind 反转（换绑后新旧两条都在、新绑置顶）。
