## 〇、价值

- **改动前（034 交互）**：侧栏「新对话」按钮旁边挂一个独立文件夹按钮，先选文件夹再开对话；选中路径挂在 `pendingWorkDir` 悬空状态上——发消息前它不属于任何会话，指挥官实测反馈"和我想的不一样，这个文件夹到底算哪个会话的？"
- **改动后**：聊天输入区「附加文件」按钮右边新增**「选择项目」**按钮，点击弹原生文件夹选框，**选完立即绑定当前会话**（按钮就在当前会话的输入区里，归属天然清晰）；「新对话」回归纯粹一键开聊，什么都不弹。

## 一、背景与问题

1. 指挥官对 034 交互的实测反馈（2026-09-29）：期望是"开新对话时选择项目文件夹"，而不是新对话按钮旁的独立按钮；并质疑悬空归属——`pendingWorkDir` 在选完到首条消息之间不属于任何会话，语义含糊（034 代码里"新会话未绑定但 pending 保留"的注释即是此含糊的自证）。
2. 指挥官拍板的新交互（2026-09-29）：**在附加文件按钮右边加「选择项目」按钮，点击选择项目**——会话进行中随时可给当前会话绑定/更换项目文件夹；「新对话」不弹任何选择。
3. 034 的后端资产（`/api/fs/pick-folder` 原生选框、meta_store work_dir 列、工具层落点与安全校验）与本次方向完全兼容，全部保留；要重构的只是前端交互接线与 work_dir 的传递通道。

## 二、目标

1. 聊天输入区「附加文件」按钮右侧新增「选择项目」按钮：点击 → `POST /api/fs/pick-folder` 弹原生选框 → 选中路径**立即**经新 REST 端点绑定当前会话 → 输入区按钮态与聊天页头部提示条同步更新。
2. **归属规则一句话**：「选择项目」永远作用于**当前会话**；新会话未选 = 落默认目录（output/<会话名>/ + downloads/<分类>/，014 行为）。已绑定后再次点击 = **更换**项目（允许，之前已落盘的文件不动，后续产物落新文件夹）。
3. 删除 034 的悬空机制：侧栏文件夹按钮 + 路径回显 chip、`pendingWorkDir` 双状态、send 首条消息带 `work_dir`、chat_ws 载荷 work_dir 处理——传递通道收敛为"选择即落库"的单条 REST 路径。
4. tkinter 失败（无显示环境等罕见场景）不再做手输兜底：聊天区直接提示错误人话（本地部署下概率极低，砍掉弹层手输 UI 的复杂度；记入 §六 可扩展）。
5. **不做**：最近使用项目列表/快捷重选（§六）；项目文件夹的展示名（直接显示路径）。

## 三、方案设计

### 3.1 后端：work_dir 绑定端点（新增）

- `POST /api/sessions/{session_id}/work-dir`，body `{path: str}`：
  - path 空 → 清除该会话 work_dir（`set_work_dir(sid, "")`）；
  - 非空 → `set_work_dir(sid, path)`（034 已有：abspath 规范化 + makedirs 自动创建 + upsert——**upsert 天然支持"meta.db 还没有该会话记录"的新会话场景**，无需等首条消息）；
  - 返回 `{ok: true, work_dir: "<规范化后的路径>"}`；mkdir 失败等异常 → `{ok: false, error: 人话}`。
- 放 `crawagent/web/routers/sessions/` 下（会话域资源，对齐现有 routers 拆包结构）。
- **删除** chat_ws 的 work_dir 载荷处理（server.py 230-237 那段"仅未设置时 set"）——中途更换由本端点承接，不再有"仅首条"限制。
- 工具层零改动（`current_work_dir()` 每次现读，绑定/更换下一轮工具调用即生效）。

### 3.2 前端：输入区「选择项目」按钮

- 位置：聊天输入区「附加文件」按钮右侧，同排同风格小按钮，文案「选择项目」（图标 + 文字）。
- 点击流：`pickFolder()`（034 已有 fetch 封装）→ 成功拿到 path → `POST /api/sessions/{id}/work-dir` → 更新 `state.workDir`；取消（canceled）→ 静默；失败 → 聊天区错误提示条。
- 按钮态：`workDir` 非空时按钮显示当前项目路径（超长省略 + hover 全文）或高亮态 + title 提示"点击更换"；无 hover 依赖的关键信息仍以聊天页头部提示条为准（034 已有，保留）。
- 删除：AppSidebar 文件夹按钮、回显 chip、手输回退弹层；useChat 的 `pendingWorkDir`/`setPendingWorkDir`/`clearPendingWorkDir`、send 里的 work_dir 携带逻辑。
- `workDir` 单状态保留：会话切换时随 `/api/history` 回读刷新（034 已有），新会话清空。
- **新会话时机细节**：新会话的 session_id 前端已生成，未发消息即可点「选择项目」——端点 upsert 直接建记录，之后首条消息无需携带任何字段（与 3.1 呼应）。

### 3.3 system.md

- 无行为契约变化（工具落点规则 034 已写：work_dir 优先 → 默认目录兜底，语义不变）。ARCHIVE-ASK 等规则不动。

### 3.4 测试

- 后端：work-dir 端点（新会话 upsert 建 / 已有会话绑定 / 更换 / 清除 / mkdir 失败人话错误 / 非法输入）；chat_ws 不再处理 work_dir（回归）。
- 前端：按钮渲染与位置、点击链路（pick → set → workDir 更新）、取消静默、失败提示、换项目二次点击、侧栏旧按钮不再存在、send 不再携带 work_dir 键。
- 基线计数同步（700 pytest + 57 vitest 起算；034 的 WS 载荷相关用例随机制删除同步调整）。

### 说明（与规格偏差）

- **WS 层 work_dir 回归用源码扫描而非真连**：chat_ws 是 WebSocket 端点，发消息即触发真实轮次（需 LLM），离线测不了；改用源码扫描锁住契约——`server.py` 不再出现 `payload.get("work_dir")` 与 `set_work_dir`（绑定只发生在 sessions/work_dir.py）。与 034 的 WS 层测试缺口同源。
- **busy 时也禁用「选择项目」**：规格未明写，但 work_dir 变更会在下一轮工具调用经 `current_work_dir()` 现读生效，中途改落点会让一轮内的产物分落两个文件夹；busy 禁用避免此混乱，UI 上两个按钮行为一致。
- **read_file 等价能力面说明**：read_file 读任意路径是有意设计（附件在 data/uploads，但用户可能让 AI 读项目里其它文件）；与 run_custom_script 能力面等价，不新增攻击面；work_dir 逃逸校验只管写工具，不影响读——此条 036 §3.2 已写明，035 无 read_file。
