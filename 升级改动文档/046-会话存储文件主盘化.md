## 〇、价值

本变更让用户对会话数据重新有掌控感、DB 体积重新可控。

**改动前**：会话内容（messages）的持久化主盘是 `data/sessions.db` 的 checkpointer state（LangGraph 每轮把整个 state 含 messages 序列化进 sqlite），sessions.db 已 1.80GB（十进制；GiB 1.68）且随使用继续涨；用户在资源管理器里看不见会话内容、备份单会话=备份整个 DB、删 `data/sessions/<sid>/` 只删归档副本不删 DB 里桥留的 state；ADR-0008 口号「文件夹管活会话」未落实——会话文件夹惰性创建，只在 save_record 触发归档时才写。

**改动后**：会话创建即建 `data/sessions/<sid>/`，每轮完成把 messages 追加到 `conversation.md`（人可读、可备份）；checkpointer 保留 sqlite 但定期清理老 state（留最近 N 轮用于断点续跑，老内容已在 conversation.md 兜底）；DB 体积可控（清理后 VACUUM 收缩文件），用户对会话数据的掌控感回归。**「删目录即清会话」按主盘语义成立**：删 `data/sessions/<sid>/` 清掉会话内容主盘（conversation.md）；DB 里最近 N 轮 checkpointer state 仍需走清理任务（§3.3）才彻底清。

## 一、背景与问题

规格期实锤（查源码 + 实地看盘，主会话审核已逐条复核 ✓）：

1. **EventLog 是进程内存 list，不在 DB**：`crawagent/web/event_log.py` 的 `EventLog` 类 `__slots__=("_events",)`，`_events: list[dict]`，append-only，重连按 cursor 增量重放（`since(cursor)`），**进程重启即清零**。它是实时事件流，与持久化/DB 体积无关——本变更不动它。
2. **sessions.db 1.80GB（十进制）主因是 checkpointer state**：`crawagent/storage/checkpointer.py:22/66` `build_checkpointer` → `SqliteSaver(conn)`，LangGraph checkpoints 表每轮把 state（含全量 messages）序列化进 sqlite，N 会话 × N 轮累积膨胀；加 FTS5 知识库内容。
3. **`data/sessions/` 目录不存在**：039 `ensure_session_folder` 惰性创建（session_folder.py:11/54 注释明文「惰性创建：首次写档案快照时 mkdir」），仅 `save_record` 触发归档双写时才 `mkdir`。本机主要跑评测/测试，从未触发归档 → 目录没建。
4. **ADR-0008 的「文件夹管活会话」是口号**：实际实现里文件夹只是归档副本（库为主、盘为副本），活会话的热数据全在 DB。

痛点：DB 膨胀不可控、用户对会话数据无掌控感（看不见摸不着）、单会话备份/迁移困难、删目录≠清会话。

## 二、目标

1. 会话创建自动建 `data/sessions/<sid>/`（含 `conversation.md` 空头 + `meta.json` + `archive/`）。
2. 每轮完成把该轮 messages 追加到 `conversation.md`（随时更新、人可读、O(1) 追加不重写全文件）。
3. **checkpointer 保留 sqlite + 定期清理老 state**（留最近 N 轮用于断点续跑，老内容已在 conversation.md 兜底，清理后 VACUUM 收缩 DB 文件）。
4. 一次性迁移：老会话从 checkpointer state 导出 messages 到各 `conversation.md`，清老 state（per-session 原子），DB 瘦身。
5. 落 ADR-0009 修正 ADR-0008（文件夹从归档副本升为会话内容主盘；checkpointer 从主盘退为运行时状态索引）。
6. 交叉影响守卫：039 蒸馏端点拒绝活跃会话触发 + 蒸馏输入集排除 conversation.md（见 §二.五）。

**不做**（划界）：
- 不改 EventLog（内存 list，与痛点无关）。
- 不改 FTS5 知识库（save_record 入库链路不动，是指挥官说的「筛选的档案信息」典型，留 DB 合理）。
- 不改 meta_store（会话标题/work_dir 绑定/时间戳，留 DB 合理；meta.json 仅作可读副本，不双向同步）。
- 不重写前端重放（EventLog 链路不动，重放逻辑零改动；**前端零改动**——清理走 CLI 脚本不走 UI 按钮，UI 按钮留 §六）。
- 不动 LangGraph agent 调用机制（checkpointer 仍是 LangGraph state 后端，只加定期清理）。

## 三、方案设计

### 3.1 会话创建即建文件夹

会话创建路径（`POST /api/sessions` 系列，实施时在 `crawagent/web/routers/sessions/crud.py` 定位具体端点）调用 `ensure_session_folder(sid)`，并在该函数内：

- 建 `data/sessions/<sid>/` + `archive/` 子目录（沿用 039 `ensure_session_folder`，从惰性改为会话创建即调）。
- 初始化 `conversation.md`（写头：会话 id、创建时间、空正文待追加）。
- 写 `meta.json`（会话标题默认值、work_dir 绑定状态、创建时间戳）。**meta.json 是可读副本**（创建时写 + 轮末更新最后活跃时间），**meta_store 仍是唯一真源**——不双向同步，避免双写一致性问题；meta_store 的 set_work_dir/set_title 不改。

### 3.2 每轮落 conversation.md

`crawagent/web/turn_engine.py` 轮末 done 事件后追加该轮（新增 `write_turn_snapshot(sid, turn_data)`，在 `_emit(... {"type":"done"})` 之后调用）：

- 追加块格式：`## 轮次 N — <时间戳>` + 用户消息原文 + 工具调用（name/args 摘要/结果摘要）+ AI 回复原文。
- O(1) 追加（`with open(..., "a", encoding="utf-8")`），不重写全文件。
- 失败不阻断主流程（类比 044 轮末 status 兜底的容错：写盘异常静默记 logger.warning，不影响 done 给前端）。**写盘段独立 try/except**——不进 turn_engine 的外层 except（否则写盘失败会被当轮次异常发 error 事件，在 done 之后再发 error 会乱）。
- **文件夹不存在时静默 skip + logger.warning**（不重建——避免与 039 archive 移走整夹的语义冲突；checkpointer 仍保最近 N 轮兜底，conversation.md 出现断带但不丢数据）。
- 追加后同步更新 `meta.json` 的「最后活跃时间」。

### 3.3 checkpointer 定期清理（CLI 脚本，用户显式运行=授权）

**选定方案：保留 sqlite + 定期清理老 state + VACUUM 收缩**

- 新增 `scripts/cleanup_checkpointer.py`（CLI 脚本，不走 UI 按钮——前端零改动；UI 按钮留 §六）。
- 保留每个会话最近 N 轮 state（N 实施时用真实数据校准，初值 10）；老的 checkpoints 记录删除前**先确认该轮已在 conversation.md**（兜底校验，防数据丢失）。
- 删除老 state 后**显式 VACUUM** 收缩 sqlite 文件（sqlite DELETE 不自动收缩，不 VACUUM 则「DB 体积下降」永远不成立）。
- **授权模型**：用户显式运行脚本即授权（沿用 ADR-0008「不自动清理」+ MCP_AUTOSTART 教训：批量动数据必须用户显式触发）；不走 ask_user（清理不是聊天时动作）。脚本启动时打印影响范围摘要 + 要求 stdin 输入 `y` 确认（二次防护）。

**备选方案 B：MemorySaver（最彻底，本次不做）**

- checkpointer 改 LangGraph MemorySaver（内存），DB 不再存 state。
- 代价：进程重启丢「进行中轮次」的断点续跑能力（已完成轮次的 messages 已在 conversation.md，不丢）；中断恢复/人工审核中间态等 LangGraph 高级特性失效。
- 适合：本地单人工具、不在意重启丢进行中轮次的使用模式。稳定后可再立 ADR 评估（§六）。

**备选方案 C：独立 state db 文件（本次不做，§六 跟进评估）**

- checkpointer state 挪到独立 db 文件（如 `data/sessions-state.db`），与 FTS5/meta 物理解耦——「清 state」变成删整个文件而非行级 prune，且不伤知识库。
- 比 MemorySaver 稳（保留断点续跑）、比行级 prune 简单。§六 跟进评估。

### 3.4 老数据一次性迁移（`scripts/migrate_checkpointer_to_files.py`）

1. **前置：服务必须停止**（避免与进行中轮次 checkpointer 写竞态）；脚本启动检查 8006 端口/进程，在跑则拒绝。
2. 迁移前自动备份 `data/sessions.db` → `data/sessions.db.bak-<timestamp>`（不可逆操作前留后路）。
3. **per-session 原子性**：遍历 checkpoints 表按 sid 分组 → 导出该会话 messages 到 `data/sessions/<sid>/conversation.md`（已存在则跳过该会话，不合并——防破坏已有内容）→ **校验导出 messages 数与 checkpointer 一致** → 校验通过才清该会话老 state（保留最近 N 轮，与 §3.3 一致）；**部分失败不清**（该会话 state 原样保留，报告里列失败会话）。
4. 全部会话处理完后 VACUUM 收缩 DB。
5. 报告：迁移会话数、导出轮次数、DB 体积前后对比（VACUUM 后实降）。

### 3.5 ADR-0009（修正 ADR-0008）

新 ADR 落 `docs/adr/0009-session-folder-as-primary-store.md`（已先行起草，本规格修订同步补方案 C 与交叉影响）：

- 修正 ADR-0008：文件夹从「归档副本」升为「会话内容主盘」；checkpointer state 从「主盘」退为「运行时状态索引（断点续跑用）」。
- Considered Options 增列方案 C（独立 state db）。
- Consequences 补 042/039 交叉影响（审计范围降为 recent N；039 蒸馏加活跃态守卫 + 排除 conversation.md）。
- 一句话：**文件夹管活会话的每轮内容，数据库管运行时状态 + 筛选的档案/元信息索引**。

### 3.6 039 蒸馏端点守卫（`crawagent/web/routers/data_manage.py`）

- **活跃态守卫**：蒸馏端点（`POST /api/data/sessions/{sid}/distill`）入口检查会话最近活跃时间（meta_store 的 work_dir_ts 或最后 checkpointer 写入时间）< 阈值（初值 24h）则拒绝，返回「会话仍活跃，归档请先等其冷却」——防 039 archive_session_folder 移走 046 活文件夹。
- **蒸馏输入集排除 conversation.md**：蒸馏读 md 时显式只取 `archive/*.md`，不读 `conversation.md`（conversation.md 是原始轮次日志，不是 curated 快照，不进蒸馏素材）。

## 五、验证方式

1. **契约测试**：会话创建后 `data/sessions/<sid>/conversation.md` 存在且有头；轮完成后（**worker 线程 join 后查，非 done 事件触发时——写盘在 done 之后**）`conversation.md` 含该轮 messages（用户消息 + 工具调用 + AI 回复）。
2. **全量 pytest**：834 基线 + 新增全绿。
3. **checkpointer 清理兜底**：造 N+5 轮会话，清理后 checkpointer 只留最近 N 轮 state，且被清的老轮次在 conversation.md 中内容齐全（兜底校验生效）；**清理后 VACUUM，DB 文件体积实降**。
4. **迁移脚本**：在 `sessions.db` 备份上跑迁移，老会话 conversation.md 生成、checkpoints 老记录清空、**DB 体积 VACUUM 后下降**（前后对比）；部分会话故意造失败 → 该会话 state 原样保留、其它会话正常迁移（per-session 原子性）。
5. **039 蒸馏守卫**：活跃会话触发蒸馏被拒（返回冷却提示）；蒸馏输入集不含 conversation.md（断言）。
6. **真机**：新建会话 → 聊一轮 → 资源管理器看 `data/sessions/<sid>/conversation.md` 出现且内容人可读；删该目录 → 会话内容主盘清（DB 里最近 N 轮 state 仍需走清理任务，已在 §〇 标明）。
