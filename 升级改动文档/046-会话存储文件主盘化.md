## 〇、价值

本变更让用户对会话数据重新有掌控感、DB 体积重新可控。

**改动前**：会话内容（messages）的持久化主盘是 `data/sessions.db` 的 checkpointer state（LangGraph 每轮把整个 state 含 messages 序列化进 sqlite），sessions.db 已 1.8GB 且随使用继续涨；用户在资源管理器里看不见会话内容、备份单会话=备份整个 DB、删 `data/sessions/<sid>/` 只删归档副本不删 DB 里桥留的 state；ADR-0008 口号「文件夹管活会话」未落实——会话文件夹惰性创建，只在 save_record 触发归档时才写。

**改动后**：会话创建即建 `data/sessions/<sid>/`，每轮完成把 messages 追加到 `conversation.md`（人可读、可备份、删目录即清会话）；checkpointer 保留 sqlite 但定期清理老 state（留最近 N 轮用于断点续跑，老内容已在 conversation.md 兜底）；DB 体积可控，用户对会话数据的掌控感回归。

## 一、背景与问题

规格期实锤（查源码 + 实地看盘）：

1. **EventLog 是进程内存 list，不在 DB**：`crawagent/web/event_log.py` 的 `EventLog` 类 `__slots__=("_events",)`，`_events: list[dict]`，append-only，重连按 cursor 增量重放（`since(cursor)`），**进程重启即清零**。它是实时事件流（轮次进行中的流式事件分发），与持久化/DB 体积无关——本变更不动它。
2. **sessions.db 1.8GB 主因是 checkpointer state**：LangGraph 的 checkpoints 表每轮把 state（含全量 messages：用户消息 + 工具调用 + AI 回复）序列化进 sqlite，N 会话 × N 轮累积膨胀；加 FTS5 知识库内容。这是「会话历史」的持久化主盘所在，也是指挥官痛点「都在 db 内」的实体。
3. **`data/sessions/` 目录不存在**：039 `ensure_session_folder` 惰性创建，仅 `save_record` 触发归档双写时才 `mkdir`。本机主要跑评测/测试，从未触发归档 → 目录没建。
4. **ADR-0008 的「文件夹管活会话」是口号**：实际实现里文件夹只是归档副本（库为主、盘为副本），活会话的热数据全在 DB。

痛点：DB 膨胀不可控、用户对会话数据无掌控感（看不见摸不着）、单会话备份/迁移困难、删目录≠清会话。

## 二、目标

1. 会话创建自动建 `data/sessions/<sid>/`（含 `conversation.md` 空头 + `meta.json` + `archive/`）。
2. 每轮完成把该轮 messages 追加到 `conversation.md`（随时更新、人可读、O(1) 追加不重写全文件）。
3. **checkpointer 保留 sqlite + 定期清理老 state**（留最近 N 轮用于断点续跑，老内容已在 conversation.md 兜底）—— **此点待指挥官批准规格时拍板**（备选 MemorySaver 最彻底但丢进行中轮次的断点续跑能力）。
4. 一次性迁移：老会话从 checkpointer state 导出 messages 到各 `conversation.md`，清老 state，DB 瘦身。
5. 落 ADR-0009 修正 ADR-0008（文件夹从归档副本升为会话内容主盘；checkpointer 从主盘退为运行时状态索引）。

**不做**（划界）：
- 不改 EventLog（内存 list，与痛点无关）。
- 不改 FTS5 知识库（save_record 入库链路不动，是指挥官说的「筛选的档案信息」典型，留 DB 合理）。
- 不改 meta_store（会话标题/work_dir 绑定/时间戳，留 DB 合理）。
- 不重写前端重放（EventLog 链路不动，重放逻辑零改动）。
- 不动 LangGraph agent 调用机制（checkpointer 仍是 LangGraph state 后端，只加定期清理）。

## 三、方案设计

### 3.1 会话创建即建文件夹

会话创建路径（`POST /api/sessions` 系列，实施时在 `crawagent/web/routers/sessions/crud.py` 定位具体端点）调用 `ensure_session_folder(sid)`，并在该函数内：

- 建 `data/sessions/<sid>/` + `archive/` 子目录（沿用 039 `ensure_session_folder`，从惰性改为会话创建即调）。
- 初始化 `conversation.md`（写头：会话 id、创建时间、空正文待追加）。
- 写 `meta.json`（会话标题默认值、work_dir 绑定状态、创建时间戳；与 meta_store 双向同步——meta_store 为主、meta.json 为可读副本）。

### 3.2 每轮落 conversation.md

`crawagent/web/turn_engine.py` 轮末 done 事件后追加该轮（新增 `write_turn_snapshot(sid, turn_data)`，在 `_emit(... {"type":"done"})` 之后调用）：

- 追加块格式：`## 轮次 N — <时间戳>` + 用户消息原文 + 工具调用（name/args 摘要/结果摘要）+ AI 回复原文。
- O(1) 追加（`with open(..., "a", encoding="utf-8")`），不重写全文件。
- 失败不阻断主流程（类比 044 轮末 status 兜底的容错：写盘异常静默记 logger.warning，不影响 done 给前端）。
- 追加后同步更新 `meta.json` 的「最后活跃时间」。

### 3.3 checkpointer 定期清理（待指挥官拍板）

**推荐方案：保留 sqlite + 定期清理老 state**

- 新增清理任务（实施时定位 checkpointer 注册点，可能落 `crawagent/graph/` 或独立脚本 `scripts/cleanup_checkpointer.py` + 高级页手动触发按钮）。
- 保留每个会话最近 N 轮 state（N 实施时用真实数据校准，初值 10）：老的 checkpoints 记录删除前**先确认该轮已在 conversation.md**（兜底校验，防数据丢失）。
- 清理走 ask_user 授权（HARD 规则：批量删数据必须用户显式触发 + 确认，沿用 ADR-0008 的「不自动清理」纪律）。

**备选方案：MemorySaver（最彻底）**

- checkpointer 改 LangGraph MemorySaver（内存），DB 不再存 state。
- 代价：进程重启丢「进行中轮次」的断点续跑能力（已完成轮次的 messages 已在 conversation.md，不丢）；中断恢复/人工审核中间态等 LangGraph 高级特性失效。
- 适合：本地单人工具、不在意重启丢进行中轮次的使用模式。

→ **规格此点待指挥官批准时拍板。实施会话按批准方案执行。**

### 3.4 老数据一次性迁移

新增 `scripts/migrate_checkpointer_to_files.py`：

1. 迁移前自动备份 `data/sessions.db` → `data/sessions.db.bak-<timestamp>`（不可逆操作前留后路）。
2. 遍历 checkpoints 表按 sid 分组，按轮次序导出每个会话的 messages 到 `data/sessions/<sid>/conversation.md`（已存在则跳过该会话或合并，实施时定）。
3. 导出成功后清对应 checkpointer 老记录（保留每会话最近 N 轮，与 3.3 一致）。
4. 报告：迁移会话数、导出轮次数、DB 体积前后对比。

### 3.5 ADR-0009（修正 ADR-0008）

新 ADR 落 `docs/adr/0009-session-folder-as-primary-store.md`：

- 修正 ADR-0008：文件夹从「归档副本」升为「会话内容主盘」；checkpointer state 从「主盘」退为「运行时状态索引（断点续跑用）」。
- 档案双写方向对调：盘为主、库为索引（save_record 入库的 FTS5 检索索引留 DB，md 快照留 archive/ 已有，方向一致）。
- 一句话：**文件夹管活会话的每轮内容，数据库管运行时状态 + 筛选的档案/元信息索引**。

## 五、验证方式

1. **契约测试**：会话创建后 `data/sessions/<sid>/conversation.md` 存在且有头；轮完成后 `conversation.md` 含该轮 messages（用户消息 + 工具调用 + AI 回复）。
2. **全量 pytest**：834 基线 + 新增全绿。
3. **checkpointer 清理兜底**：造 N+5 轮会话，清理后 checkpointer 只留最近 N 轮 state，且被清的老轮次在 conversation.md 中内容齐全（兜底校验生效）。
4. **迁移脚本**：在 `sessions.db` 备份上跑迁移，老会话 conversation.md 生成、checkpoints 老记录清空、DB 体积下降（前后对比）。
5. **真机**：新建会话 → 聊一轮 → 资源管理器看 `data/sessions/<sid>/conversation.md` 出现且内容人可读；删该目录 → 会话内容随之清（DB 里 checkpointer 老记录按清理策略处理）。
