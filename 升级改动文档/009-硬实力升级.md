## 〇、价值

- **改动前**：run_custom_script 现场 pip 装包超时（markitdown 单包 100s 装不完）；save_record 无质量过滤，垃圾页照入库；只有爬虫工具，没有文件转换 / 整站遍历 / AI 浏览器交互。
- **改动后**：crawl4ai / markitdown[all] / browser-use / scrapling / curl_cffi 预装进 .venv，脚本直接 import；save_record 五关过滤拒垃圾入库；三个高级工具（文件转 md / 整站深度抓 / LLM 驱动浏览器）注册进工具箱。CrawAgent 从「爬虫」升级成「带文件转换、整站遍历、AI 浏览器操作 + 质量门控的爬虫」。

## 一、任务 1：预装依赖 + 修冲突

- 清华镜像 `uv pip install crawl4ai "markitdown[all]" browser-use scrapling curl_cffi` 装进 .venv。
- **冲突**：装包把 `mcp` 换成 2.1.1 新变体（无 `RequestContext`），`langchain-mcp-adapters 0.3.2` import 崩 → 连带 CrawAgent 的 MCP 装载（get_mcp_tools）全坏。修法：`uv pip install --upgrade langchain-mcp-adapters`（重装 + 修传递依赖 websockets 15→17 等），`import MultiServerMCPClient` 恢复，browser-harness 的 23 工具装载回归。
- **openai 2.54.0 → 2.26.0** 被 browser-use 钉降级——实测 CrawAgent 全量回归通过，未破坏 langchain-openai 1.5.0 兼容。
- `crawl4ai-setup` 下 Chromium + DB 迁移完成。

## 二、任务 2：save_record 五关过滤

`crawagent/tools/quality_filter.py`（新增），阈值全提成顶部常量：

| 关 | 指标 | 阈值 | 判定 |
|----|------|------|------|
| ① 长度 | 正文长度 | <200 字 | 淘汰 |
| ② 信噪 | 正文/正文HTML | <15%（传 html 才判） | 淘汰 |
| ③ 去重 | md5(前500字) | 已存在 | 跳过（[DUPLICATE]） |
| ④ 价值 | 标题+结构 | 无标题或无结构（单行无段落/列表/标题标记） | 淘汰 |
| ⑤ 类型 | 链接文字比>25%（有 html）或 营销词≥3 且代码密度<2/千字 | — | 淘汰（索引/营销页） |

- save_record 加 `html` 可选参数（agent 手头有 crawl_webpage 原始返回时可传，让②⑤生效）。
- `content_md5` 列迁移（ADD COLUMN 幂等）；淘汰记录落 `rejected_records` 表（审计）。
- 返回：`Saved` / `[REJECTED] <原因>（已记入 rejected_records）` / `[DUPLICATE] 与已有 ID X 相同`。
- FTS 触发器不受影响（拒/跳过时不 INSERT，触发器不触发）。

## 三、任务 3：三个高级工具（`advanced_tools.py`）

| 工具 | 底层 | 何时调 |
|------|------|--------|
| `markitdown_convert(file_path)` | markitdown | 用户有本地文档要转文字（PDF/Word/Excel/PPT/图片） |
| `crawl4ai_deep_crawl(url, max_pages=50)` | crawl4ai AsyncWebCrawler + BestFirstCrawlingStrategy(max_depth=3) | 整站/文档站一次性抓多页 |
| `browser_use_navigate(url, task)` | browser-use Agent + Browser(headless=False) | 页面需登录/点击/填表交互（最重，非交互不用） |

### browser-use LLM 配置（任务 4，选项 A）

browser-use 0.13 不认裸 langchain ChatOpenAI（要 `.provider`）。用 `browser_use.llm.openai.like.ChatOpenAILike(model, api_key, base_url)` —— 专给 OpenAI 兼容端点，有 `.provider`。复用 `crawagent.llm.registry.resolve_model(None)` 解析 .env 的 provider 配置传入。无需单独 key。
