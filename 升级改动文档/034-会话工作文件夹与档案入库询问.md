## 〇、价值

- **改动前**：产物只能落项目 `output/<会话名>/` 与 `downloads/<分类>/`（014），用户想存到自己的位置（如 `D:/资料/一加官网/`）只能事后手动搬；重要抓取内容是否入知识库档案由 AI 自觉决定，用户无感知、无决策权。
- **改动后**：新建对话时点一下按钮，弹出 **Windows 原生文件夹选择框**，选中的文件夹就是本会话的工作文件夹——文本、媒体、脚本产物全部直接落那里；抓取类任务完成时 AI 主动用选择题问「本次内容要存入档案吗」，存不存用户拍板。

## 一、背景与问题

1. 014 把文本产物默认落 `output/<会话名>/`（会话间隔离），指挥官实测后反馈：高级设置里设了「产物目录」，但产物实际按会话分组落子目录，感觉"设置被架空"；用户真正想要的是**会话级指定存放位置**，选了就直接用，不再套会话子目录。
2. 指挥官对路径选择的体验要求明确：**点击后跳出文件资源管理器选择文件夹**——不是手输路径。浏览器沙箱（`showDirectoryPicker` 等 File System Access API）出于安全只返回句柄、拿不到完整绝对路径，前端方案走不通；本项目是**本地单机部署**（ADR 定位，无鉴权），WebUI 服务进程就在用户本机，由**后端弹原生对话框**（tkinter 标准库）完全可行且体验最正。
3. 知识库 `save_record`（变更 008，FTS5 全文检索）已具备"档案"的全部存取与检索能力，但入库时机由 AI 自行判断，用户既不知道存了什么、也没有说"不"的机会。项目既有哲学是「需要用户决策的事走 ask_user 选择题」（与"禁止静默拉起服务"同源），档案入库应纳入。

## 二、目标

1. 新建对话处可选**工作文件夹**：点击按钮弹出系统原生文件夹选择框（后端 tkinter 实现），选中路径回显、可清除；本会话**全部产物**（文本 / 媒体 / 脚本产物）**直接落所选文件夹**（不套会话子目录）。
2. 不选工作文件夹的会话维持现状行为（`output/<会话名>/` + `downloads/<分类>/`），014 语义保留为兜底。
3. 抓取类任务完成时，AI 用 ask_user 问「本次抓取的内容要存入档案吗？」（存入档案 / 不用 / 本会话不再询问）；存入即调 `save_record` 入知识库。
4. **不做**：已有会话中途改工作文件夹（记入 §六）；远程/局域网他机访问场景的文件夹选择（弹窗只对服务端本机有意义）；档案分类目录体系（沿用 008 现状）。

## 三、方案设计

### 3.1 原生文件夹选择端点：`POST /api/fs/pick-folder`

- 后端起 **daemon 线程**跑 `tkinter.filedialog.askdirectory()`（`root = tk.Tk(); root.withdraw(); root.attributes('-topmost', True)`，选完 `destroy()`）——绝不能在 uvicorn 事件循环线程弹（会卡死服务）。端点阻塞等待至用户选完，返回 `{ok: true, path}` / `{ok: true, canceled: true}`；tkinter 异常（无显示环境等）返回 `{ok: false, error}`，前端回退**手输路径输入框**（保底交互）。
- 并发防抖：进程级标志位，正在弹窗时的二次请求直接返回 `{ok: false, error: "选择框已打开"}`。
- 路由放 `crawagent/web/routers/` 下新文件（`fs.py`）或挂现有 routers，实施时按 routers 拆包结构对齐。

### 3.2 work_dir 会话级存储（meta_store）

- meta.db 会话表新增 `work_dir TEXT DEFAULT ''` 列（老库 ALTER TABLE 兼容迁移，参照现有列迁移写法）。
- 新建会话 API 接受可选 `work_dir` 参数：服务端 `os.path.abspath` 规范化 + 目录存在则直接用、不存在**自动创建**（mkdir parents）后入库；空/缺省 = 不设置。
- 读取：`get_work_dir(session_id)`，无记录或空返回 `""`。

### 3.3 工具层落点改造（核心）

`session_dir.py` 新增 `current_work_dir()`：`ctx_session_id → meta_store.get_work_dir()`，全程吞异常返回 `""`（与 `session_subdir()` 同款防御）。

- **save_to_file**（file_tool.py `_resolve_file_path`）：`current_work_dir()` 非空 → 以 work_dir 为基准直接落 `work_dir/<subdir?>/`（subdir 空 = 落 work_dir 根，**不套会话目录**）；**路径安全校验基准同步改为 work_dir**（`is_relative_to(work_dir)`），防 AI 借工具写所选文件夹之外。
- **媒体下载工具**：基准从 `downloads_dir` 改为 work_dir（非空时），工具自身分类 subdir（如 `images/`、`video/`）**保留**——分类是工具语义，用户否掉的是"会话子目录"那一层。涉及工具实施时 `grep -l downloads_dir crawagent/tools/` 全量清点（download_images / download_social_media / wallpaper 系等）。
- **run_custom_script**：work_dir 非空时 `SESSION_SUBDIR` 注入**空串**（脚本产物直接落 work_dir 根，与 save_to_file 语义对齐）。
- **system.md 同步**：产物路径描述改为「会话配置了工作文件夹 → 全部产物直接落该文件夹；未配置 → 文本落 output/SESSION_SUBDIR/、媒体落 downloads/<分类>/」。

### 3.4 前端：新建对话选工作文件夹

- ChatPage 侧栏「新建对话」按钮旁新增**文件夹图标按钮**：点击 → `POST /api/fs/pick-folder` → 原生框弹出 → 选中后按钮旁回显路径（超长省略 + hover 全文），带 **× 清除**；弹窗失败自动切手输输入框（保底）。
- 创建会话的首条消息请求带上 `work_dir`（仅当用户选了）；会话创建后回读快照展示。
- 聊天页头部（或 trace 区）显示当前工作文件夹，让"产物会去哪"始终可感知。
- useChat.js 增加工作文件夹状态（模块级组合式单例，随会话切换刷新）。

### 3.5 档案入库询问（system.md 行为契约）

- 新增硬规则：**抓取类任务完成时**（browse_and_crawl 深抓 / crawl_webpage 多页抓取 / download_* 批量下载 / browser_use_navigate 内容提取等），AI MUST 用 `ask_user` 问：「本次抓取的内容要存入档案吗？」选项：`存入档案` / `不用` / `本会话不再询问`。
- 用户选「存入档案」→ AI 整理本次正文为 `save_record`（title = 任务主题，content = 抓取正文/结构化结果，超长按 008 现有截断策略）。
- 「本会话不再询问」→ AI 在本会话后续不再弹（对话上下文自持，不落库）。
- **不问**的场景：单页速览、失败/空结果任务、用户明确说"不用存"之后。
- ASK-USER 硬规则区同步条数与表述。

### 3.6 测试

- 后端：pick-folder 防抖与 canceled/mock tkinter 路径；work_dir 列迁移 + 读写；save_to_file work_dir 路由（根/subdir/逃逸拒绝）；媒体工具落点跟随；run_custom_script SESSION_SUBDIR 空串注入；未配置 work_dir 行为回归不变。
- 前端：文件夹按钮弹窗调用、路径回显/清除、创建请求携带 work_dir、失败回退手输。
- 基线计数同步（680 pytest + 53 vitest 起算）。

## 八、实施记录（2026-09-29）

### 怎么做到的（人话版）

分五块落地：

1. **meta_store（`crawagent/storage/meta_store.py`）**：`session_titles` 表补 `work_dir TEXT DEFAULT ''` 列——建表后挂 `_migrate_meta_columns()`（PRAGMA table_info 探列 + ALTER TABLE，duplicate column 忽略，与 save_tool `_init_db` 同款写法），老库连上即自动补列。新增 `get_work_dir()`（无记录/空/异常返回空串）与 `set_work_dir()`（`os.path.abspath` 规范化 + `os.makedirs` 自动创建 + upsert，upsert 用 `ON CONFLICT DO UPDATE` 只动 work_dir 不清已有标题；空串 = 清除）。
2. **pick-folder 端点（新增 `crawagent/web/routers/fs.py`，server.py 挂载）**：`POST /api/fs/pick-folder` 起 daemon 线程跑 tkinter——每次新建 `tk.Tk()` → `withdraw()` → `-topmost` → `askdirectory(title="选择本会话的工作文件夹")` → `destroy()`，绝不碰事件循环线程；经 asyncio Future 桥接回协程阻塞等待。三路返回：选中 `{ok,path}`、取消 `{ok,canceled:true,path:""}`、异常 `{ok:false,error}`；进程级 `_picking` 标志防抖，弹窗未关时二次请求直接 `{ok:false,error:"选择框已打开"}`。
3. **工具层落点（034 核心）**：`session_dir.current_work_dir()`（ctx_session_id → get_work_dir，全程吞异常，与 session_subdir 同款防御）。`file_tool._resolve_file_path` work_dir 非空时以它为基准（subdir 空/"output" 落根、其余落 work_dir/<subdir>/，不套会话目录），**安全校验基准随迁** `is_relative_to(work_dir)`——`../逃逸` 与绝对路径都被拒；未配置走原 014 逻辑零变化。媒体两处（`download_images._resolve_out_dir` 抽成纯函数、`download_social_media` 内联分支）work_dir 非空时基准换工作文件夹、分类/平台子目录保留、逃逸拒绝；social 顺带把 startswith(project_root) 升级为 `is_relative_to(downloads_root)`（prefix confusion 防御）。`run_custom_script` 抽 `_script_format_kwargs()`：work_dir 非空时 output/downloads 都指向工作文件夹、SESSION_SUBDIR 注入空串（脚本两条落点约定都进工作文件夹根）；PROJECT_ROOT 恒为真实项目根（get_site_profile/browser_render 依赖 PROJECT_ROOT/data）。
4. **前后端接线**：会话创建是隐式的（前端生成 ID、首条 WS 消息触发），所以 work_dir 透传走 `chat_ws` message 载荷——服务端仅在该会话尚未设置时 `set_work_dir`（首条消息语义），目录创建失败打印日志后退回默认落点不阻断本轮；`/api/history/{id}` 响应补 `work_dir` 字段供刷新/切会话回读。前端 useChat 加 `workDir`（当前会话已生效）与 `pendingWorkDir`（选好待生效）双状态 + `pickFolder/setPendingWorkDir/clearPendingWorkDir`；AppSidebar「新对话」旁文件夹图标按钮（弹窗中禁用防重复点），选中路径回显条（超长省略 + hover 全文 + × 清除），tkinter 失败自动切手输路径框（回车或确定提交）；`send()` 首条消息带 `work_dir` 并乐观置位；ChatPage 头部工作文件夹提示条（工作文件夹 + 路径，始终可感知）。
5. **system.md 契约同步**：save_to_file/download_* 工具描述、脚本 PROJECT_ROOT 落点段、DOWNLOAD PATH RULE 全部加 work_dir 优先语义；**ARCHIVE-ASK RULE（HARD）**新增在 ASK-USER 区——抓取类任务完成 MUST ask_user「本次抓取的内容要存入档案吗？」（存入档案/不用/本会话不再询问），存入即 save_record（008 截断策略），"本会话不再询问"对话上下文自持；同时把 RETRIEVE-FIRST 与 DETAIL 工作流第 4 步里两处"抓取成功即自动 save_record"改为指向 ARCHIVE-ASK（消解新旧规则冲突，静默入库从 MUST 变成违规）。
