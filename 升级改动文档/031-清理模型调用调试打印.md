## 〇、价值

- **改动前**：`graph/middleware.py` 的两个 `wrap_model_call` 路径里，**每次模型调用都会无条件 `print()` 5~8 行**，其中包括把 `request.state` 的每个 key 做 `repr()` 截断 200 字符、以及 `request.config` 的完整 repr。**没有任何开关保护**，Web 端走 asyncio 路径（`awrap_model_call`），所以生产会话里每一次 LLM 调用都在刷屏。
- **改动后**：这些纯调试输出被删除；剩余的、有运维价值的输出（如"水位淘汰触发"）改用项目统一的 `structlog`；stdout 恢复干净，日志可按级别过滤。
- **附带收益**：这是**一次真实的人工 review 成果** —— 它能证明"AI 生成的代码经过了人的把关"，而不是直接落地。

## 一、背景与问题

### 1.1 现象

在一次真实会话中，模型调用路径会输出：

```
[MIDDLEWARE] wrap_model_call ENTER
[MIDDLEWARE] ✅ thread_id = 'xxxx'
[MIDDLEWARE] max_tokens = 44,800 (model=deepseek-v4-flash)
[ASYNC-MW] awrap_model_call ENTER
[ASYNC-MW] state keys = ['messages', '__runnable_config', ...]
  state['__runnable_config'] = {...截断 200 字符...}
[ASYNC-MW] request.config = {...}
[ASYNC-MW] request type = ModelRequest
[METRICS] on_llm_end: prompt=12345, completion=678, cache_hit=11000, cache_miss=1345, ...
```

一个 100 次 LLM 调用的会话 = **约 600~800 行非结构化输出**。

### 1.2 影响

1. **污染 stdout**：Web 服务日志、容器日志、CI 输出全部被这些行淹没，真实告警反而不显眼。
2. **无法按级别过滤**：项目已经统一用 `structlog`（`app.core.structlog` 同款风格，CrawAgent 里 `log = structlog.get_logger(...)` 多处使用），唯独这些点还是裸 `print`。
3. **有信息泄露面**：`state` / `config` 的 repr 会打印会话内部的运行配置（模型名、thread_id 等），在多用户部署时会写进共享日志。
4. **性能**：`flush=True` 强制刷盘 + 每次调用做多次 `repr()`，在长会话里是可测量的开销。

### 1.3 根因

AI 辅助开发期间的调试打印**未被清理**，且**从未被 review 拦下**（同类问题在 `observability/metrics.py:222` 甚至留着 `# DEBUG:` 注释，说明作者知道是临时的，但一直没删）。

## 二、目标

### 2.1 要做

1. **删除**模型调用路径上的纯调试打印（下表 A 类）
2. **转换**有运维价值的低频输出为 `structlog`（下表 B 类）
3. 保持**行为完全不变**：只动输出方式，不动任何逻辑、阈值、分支

### 2.2 不做（明确划出边界）

- ❌ **不动 `tools/script_tool/header.py` 与 `runner.py` 的 print** —— 那是**生成脚本与宿主之间的输出协议**（`FINAL_URL:` / `HTML_LEN:` / 结果 JSON），删了工具直接失效
- ❌ 不动 `cli.py` 的 print —— 那是命令行 UI
- ❌ 不动 `observability/metrics.py:136` 的 `print(m.status_line())` —— 那是终端状态栏的有意输出
- ❌ 不动 `dist/` 下的 print —— 独立进程（worker / redis-server）的启动日志，无 structlog 上下文
- ❌ 不引入日志级别配置项、不改 structlog 初始化（属另一个规格）
- ❌ 不顺手重构 middleware 的逻辑

### 3.2 示例 diff（A 类，`middleware.py`）

```python
# 修前
    def wrap_model_call(self, request, handler):
        """裁剪 request.messages 后再调 handler。不修改 request.state。"""
        print(f"[MIDDLEWARE] wrap_model_call ENTER", flush=True)

        original_messages = request.messages
        if not original_messages:
            return handler(request)

        thread_id = self._scan_thread_id(request)
        print(f"[MIDDLEWARE] ✅ thread_id = {thread_id!r}", flush=True)
```

```python
# 修后
    def wrap_model_call(self, request, handler):
        """裁剪 request.messages 后再调 handler。不修改 request.state。"""
        original_messages = request.messages
        if not original_messages:
            return handler(request)

        thread_id = self._scan_thread_id(request)
```

### 3.3 验收标准

1. `uv run pytest tests/ -q` —— **603 全绿**（基线不变）
2. `cd web && npm test` —— **43 vitest 全绿**
3. 手工冒烟：起服务跑一轮多步会话，确认 stdout 里**不再出现** `[MIDDLEWARE]` / `[ASYNC-MW]` / `[METRICS]` / `[THINKING]`
4. 手工冒烟：触发一次历史裁剪（长会话），确认 `trim_evicted` 以结构化日志形式输出
5. **确认没有任何测试依赖被删的输出**：已核查 `tests/` 下无 `capsys` / `capfd` 用例，且无断言涉及上述字符串（`test_script_tool.py` 里的 `stdout=` 是 mock 子进程返回值，与本变更无关）

| 风险 | 等级 | 处置 |
