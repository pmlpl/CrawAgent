## 〇、价值

本变更让用户在「AI 干了很久的活却一句话不说」的场景获得改善——改动前：长任务轮次（10+ 工具调用）偶发以一条**完全空白的最终回复**收尾，轮次正常 done，用户看到 AI 停在那里不知发生了什么，只能自己猜；改动后：轮次引擎在模型哑火时自动换路重试（最多两级），重试仍空则明确提示用户「成果未丢，回复继续即可让它重新总结」——沉默轮从「无解」变成「自愈或一句话说清」。

## 一、背景与问题

043 真机验收同场的 Agent 水平实测（2026-10-04，会话 realcap-20261004）中，两次长轮次以空气回复收尾：

1. **抖音第 1 轮**（11 次工具调用）：最后一次 `browse_and_crawl` 返回验证码页后，模型应总结失败原因——checkpoint 里最后一帧 AIMessage `content` 与 `reasoning_content` 均为空、无 tool_calls，`response_metadata.finish_reason = 'length'`。
2. **壁纸第 1 轮**（10 次工具调用）：同样的空回复收尾，同样 `finish_reason='length'`。

**根因链**：`THINKING_DEPTH=high`（.env 全局）→ glm-5.2 中转在长上下文下思考 token 极长 → **中转侧输出配额被思考全部吃光** → 正文零字符即被 `length` 截断 → 轮次图循环见「无 tool_calls 的 AIMessage」正常收尾 → turn_engine 照常 `done`。这与变更 033 时代「小 max_tokens 全被 reasoning_content 吃光」是同一机制在真机长轮次的复现（033 只在探测小预算场景修过探测判定，主链路从未设防）。

**影响**：短轮次从未命中（本会话 9/11 轮正常），长轮次命中率高（当天 2/2 的 10+ 工具轮全部哑火）——恰好用户最需要总结的重活反而没下文。轮次引擎对空最终消息零检测零兜底。

## 二、目标

1. 中间件层自动换路：模型返回「空最终回复」时，先原样重试一次（瞬时抖动假设），仍空则换 thinking-off 模型再试一次（思考吃配额假设）——两次都失败才把空回复交给轮次收尾。
2. 轮次引擎兜底提示：重试后仍空时，向用户发一条明确的状态行（人话说明发生了什么、成果没丢、怎么继续），消灭静默 done。
3. 正常回复零干预：中间件对非空/带 tool_calls 的回复完全透明，不增加延迟与缓存破坏。

**不做**（划界）：
- 不改 `THINKING_DEPTH` 默认值（high 是否降档是体验取舍，另行拍板）。
- 不做合成 AI 消息（伪造模型输出污染会话语义，agent 下轮不知道自己"说过"什么）。
- 不做跨轮熔断/计数器（空回复是低频事件，两级重试已够）。
- 不动 TrimHistory / ScriptForcer 的既有逻辑。
- 042 审计签名表补「验证码中间页」（P2）不在本变更，见 §六。

## 三、方案设计

### 3.1 判定函数（`middleware.py` 新增 `_is_empty_final_reply(msg) -> bool`）

```python
isinstance(msg, AIMessage)
and not getattr(msg, "tool_calls", None)            # 带 tool_calls = 中间步，永不触发
and not (str(getattr(msg, "content", "") or "")).strip()
```

- `reasoning_content` 有内容也不算回复（用户看到的正文是空的）。
- content 为 list（多模态）时取文本块拼接后判空。
- 对 structured output / tool_choice 场景天然免疫（那些路径必有 tool_calls 或非空 content）。

### 3.2 EmptyReplyRetryMiddleware（`middleware.py` 新增，注册进 agent）

`wrap_model_call(request, handler)`：

```python
result = handler(request)                # 第一次：正常调用
if not _is_empty_final_reply(result):
    return result
# 一级：原样重试（瞬时抖动假设）；messages 不变 → 前缀缓存无损
result = handler(request)
if not _is_empty_final_reply(result):
    return result
# 二级：换 thinking-off 模型（思考吃配额假设）
retry_model = self._thinking_off_model()          # get_llm(thinking=False)，实例缓存在 self
result = handler(request.override(model=retry_model))
return result                                      # 仍空也原样返回，交给 3.3 兜底
```

- **换模型的安全性**：`langchain/agents/factory.py:1435` 每次 `request.model.bind(**request.model_settings)` 重新绑工具——override 换裸模型实例后工具绑定行为等价，已实读源码确认。
- **thinking-off 实例缓存**：`get_llm()` 每次新建无缓存，middleware 用 `self._retry_model` 惰性建一次复用。
- **观测**：每次触发重试 print `[EMPTY_REPLY_RETRY] step=1|2 finish_reason=... len_messages=...`，真机可统计命中率。
- **防重入**：只对「无 tool_calls 的空回复」触发，该形态按定义是图循环的终结步，天然不会连环。
- **异常回退**：重试段整体包 try/except，任何异常返回第一次的 result——中间件永不比现状更差。
- **注册顺序**：`middleware=[trim_middleware, empty_reply_retry, script_forcer]`——重试包在最外层语义（trim 改请求侧、script_forcer 注入强制消息，均先于重试执行）；实施时跑单测验证嵌套顺序与预期一致。

### 3.3 turn_engine 轮末兜底（`turn_engine.py`，graph 循环结束后）

```python
final_msgs = final_state 最后一条 AIMessage
if _is_empty_final_reply(final_msgs):
    _emit(session_id, q, loop, {"type": "status", "line":
        "⚠️ 模型本轮没有产出最终回复（思考占满输出预算被截断）。"
        "本轮成果都在，回复「继续」我会重新总结。"})
```

- 只发 status 行，不改 done 语义、不写 session_error 红条、不合成 AI 消息。
- 阈值：重试上限固定 2 次（行为型参数，无需数据校准）。

### 3.4 边界与回退

- 中转偶发 200-空（非 length）同样被一级重试覆盖——判定只看内容，不依赖 finish_reason（finish_reason 仅进观测日志）。
- 空回复若出现在**中间步**（极罕见：模型空转后下一轮又调工具）——不会触发：判定要求无 tool_calls，LangGraph 循环对空消息无 tool_calls 即终结，二者一致。
- 服务降级路径：重试二级依赖 get_llm 可用；LLM 整体挂掉时 handler 本身抛错，中间件不拦（保持现状语义）。

## 八、实施记录（2026-10-04）

### 怎么做到的（人话版）

AI 干活时如果「想得太多」，思考 token 会把模型输出配额整个吃光，正文一个字都挤不出来——用户看到的就是 AI 忙完半天后一言不发。这次给它装了个「哑火重试器」：模型一旦交白卷，先原样重试一次（防瞬时抖动），还哑就把思考关掉换个模型再答一次（防思考吃配额）；两级都救不回来，轮次收尾时明确告诉用户「成果都在，回复继续就能重新总结」。重试用的是同一段对话上下文，缓存完全不受影响；正常回复走原路零干预。

### 验证结果（对照 §五）

1. **单测**：`tests/test_empty_reply_retry.py` 13 例全绿——判定（空文本/空白/多模态空、带 tool_calls 不触发、非 AIMessage 不触发）、一级原样重试收敛、二级换 thinking-off（哨兵模型实证 `override(model=)` 生效）、三连空原样返回、一级/二级异常回退、首调异常上抛、裸 AIMessage 兼容、结构化输出 ToolMessage 尾部不误判、轮末 status 含「继续/成果」话术、正常轮零 emit、get_state 异常不阻断。
2. **全量回归**：pytest **833 全绿**（820 + 13）；vitest **80 全绿**（前端零改动，保险跑，未 build）。
3. **040 评测回归**：黄金集 20 例 **16/20 = 80.0%**，落在既有基线带下沿（041 记录：85% 带、80% 下沿），判「分数不降」；全程 `[EMPTY_REPLY_RETRY]` 触发 **0 次**——中间件零干预的直接证据。4 个 FAIL：01/18 为已知间歇家族（挂账项），03/20 为单跑方差（040 门槛：同例连续两次 FAIL 才算回归，建议下批前复跑观察）。
4. **搭车 042 复核**：`scripts/audit_sessions.py --all` 16 会话 82 轮，realcap 会话的「验证码中间页」R2 误报消失；余下 5 R2 + 2 R3 全为其他历史会话（042 首批已复核范围），无新增命中。

### 说明

- **与规格的一处偏差**：规格 §3.2 写「注册在 middleware 列表末位」，实施放在**首位**——实读 langchain 源码确认「first in list = outermost」，重试器要包在最外层才能让 handler 重跑完整经过 trim/script_forcer 内层链，规格该处笔误。
- 二级换路模型按规格用 `get_llm(thinking=False)` 并在中间件实例内惰性缓存（get_llm 无 lru 缓存，避免每次重建）。
- handler 返回类型实测为 `ModelResponse`（`result: list[BaseMessage]`），判定取 `result[-1]`；结构化输出路径尾部是 ToolMessage，天然不判空、不重试（有专例锁定）。
- 重试上限固定 2 次（行为型参数，无需校准）；`[EMPTY_REPLY_RETRY]` 日志留真机统计命中率。
- 搭车项：042 签名校准随本批入库（指挥官批准规格时一并同意）。
- 本变更随 commit 51659a6 提交入库；测试数据 eval_044.json 确认无需保留后可删除。
