# 012 — 聊天框内联播放抓取视频（trace step 媒体渲染）

## 背景

工具下载视频后，文件落在 `downloads/` 下、绝对路径已写进工具结果（`download_social_media` 返 JSON 含 `downloaded[].{path,type}`；`download_images` 返文本含 output dir + 文件名）。但工具结果经 `tool_result` 事件原样转发 `content`，前端存到 trace step 的 `result` 当**纯文本**渲染（CrawlTrace.vue `<details>` 折叠区），且**下载目录没挂 HTTP 路由**、**聊天无 `<video>` 渲染**。用户抓完视频得去文件夹里翻着看，断链于「抓取→观看」。

本变更补两件事：① FastAPI 服务下载目录（Range 支持，可拖进度条）② 后端从工具结果提取媒体路径挂到事件、前端在 trace step 渲染 `<video>/<img>/<audio>`。

## 设计决策（grill-with-docs 共识）

1. **渲染在 trace step 内**（非新顶层 `kind:'media'` 气泡）：视频是工具输出，挂产生它的 trace step 最内聚、不与 trace 重复。step 含媒体时 `<details>` 自动展开求显眼。
2. **StaticFiles mount 服务下载目录**：`app.mount("/downloads", StaticFiles(directory=downloads_dir))`——Starlette 原生支持 HTTP Range（seek/拖动正常）+ 防路径穿越。本地部署无鉴权（P2-6 已定不做）。
3. **后端提取媒体路径**：加 `_extract_media(content)` helper（**按内容格式检测**，不依赖 tool_name——JSON 试 `downloaded[]` / 文本 regex `output dir:`），返回 `[{path,url,type,filename}]`，`url` 由后端算好（`path.relative_to(downloads_dir).as_posix()` → `/downloads/rel/path`，Windows 反斜杠自动转正）。挂到 `tool_result` 事件的 `media` 字段，前端只读 `e.media`。
4. **全媒体范围**：视频 `<video controls>` + 图片 `<img>` + 音频 `<audio controls>`——同一份工具结果常含混合（视频+封面+音频），增量极小，别只做视频回头补。
5. **两处 emit 站点都接 helper**：turn_engine 快照分支（live 轮次）+ sessions `_reconstruct_messages`（历史重放/刷新重连）都调 `_extract_media`，保证刷新后视频仍在。

## 改动清单

### 后端 `crawagent/web/server.py`
- `main()` 里 `downloads_dir` 存在则 `app.mount("/downloads", StaticFiles(directory=str(downloads_dir)), name="downloads")`——挂载晚于 API/WS 路由注册（与 `/assets` 同位置，server.py:323 附近）。`downloads_dir` 由 `get_settings()` 给，`mkdir(parents=True, exist_ok=True)` 已在启动期做。

### 后端 `crawagent/web/routers/sessions.py`
- `_reconstruct_messages` 发 `tool_result` 事件处（约 126-134 行）：对每条 tool 内容调 `_extract_media(content)`，把 `media` 字段并进事件 dict。

### 后端 `crawagent/web/turn_engine.py`
- 快照分支发 `tool_result` 事件处（约 388-394 行）：`media = _extract_media(content)`，事件 dict 加 `"media": media`（可能空 list）。

### 后端 helper（新模块或并入 `sessions.py`/`turn_engine` 共用）
`_extract_media(content: str) -> list[dict]`：
- 先 `json.loads`：成功且含 `downloaded` 列表 → 遍历取 `type in (video/image/audio)` 且 `path` 存在的项
- 否则文本 regex：匹配 `output dir:\s*(.+)` 取目录 + 行内 `(\S+\.(mp4|webm|mov|jpg|png|webp|mp3|m4a))` 取文件名，拼绝对路径
- 每项返 `{"path": abs, "url": f"/downloads/{rel_posix}", "type": video|image|audio, "filename": name}`
- `rel` = `Path(abs).relative_to(downloads_dir)`，越界（不在 downloads 下）跳过
- 空结果返 `[]`

### 前端 `web/src/composables/useChat.js`
- `pushToolResult(content, toolCallId, media=[])`：签名加 `media`，存到 `step.media = media`（默认 `[]` 保旧调用兼容）
- `handleEvent` 的 `case 'tool_result'`：`pushToolResult(e.content, e.tool_call_id, e.media || [])`

### 前端 `web/src/components/CrawlTrace.vue`
- step 渲染加媒体块（`step.media` 非空时，在 `step.result` 文本块**上方**显眼位）：
  ```vue
  <div v-if="step.media?.length" class="step-media">
    <template v-for="m in step.media" :key="m.url">
      <video v-if="m.type === 'video'" :src="m.url" controls preload="metadata" class="step-video" />
      <img v-else-if="m.type === 'image'" :src="m.url" :alt="m.filename" class="step-img" />
      <audio v-else-if="m.type === 'audio'" :src="m.url" controls preload="metadata" class="step-audio" />
    </template>
  </div>
  ```
- `<details :open="...">` 的 open 判定加 `|| step.media?.length`（有媒体自动展开）
- 加 CSS：`.step-video { max-width: 100%; max-height: 360px; border-radius: 8px; }` `.step-img { max-width: 100%; border-radius: 8px; }`

## 不做

- 不加鉴权（本地部署，P2-6 同款）
- 不做顶层 `kind:'media'` 气泡（trace step 内嵌最内聚）
- 不动工具返回格式（工具照旧返字符串，后端解析）
- 不做视频转码/缩略图（文件原样服务）
- AI 生成视频不在范围（只处理「抓取下载」的媒体）

## 验收

- 用 `download_social_media` 抓一条抖音/B站视频 → trace step 自动展开显示 `<video>` → 可播放 + 拖进度条（Range 生效）
- 抓壁纸/图片（`download_images`）→ step 显示 `<img>`
- 刷新页面/重连 → 视频仍在（历史重放走 `_reconstruct_messages` 也挂了 media）
- 视频文件路径穿越 `../../../etc/passwd` → 404/拒绝
- 基线 225 pytest + 10 vitest + 新测试全绿

## 风险

- **StaticFiles 目录不存在**：mount 时 dir 缺失会启动报错——`downloads_dir` 在 `main()` 启动期已 `mkdir`，挂载前确保（与 log_dir 同款处理）
- **大视频内存**：StaticFiles 流式响应不走内存，OK；`preload="metadata"` 不预加载全片
- **CORS**：同源（5173 dev / 8006 prod 同站），无跨域问题
- **历史重放 media 重复提取**：`_extract_media` 纯函数幂等，重复调无副作用
