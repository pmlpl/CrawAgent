## 〇、价值

- **改动前**：加/删/停用 MCP server 只能去设置页「生态扩展」页签 GUI 填表。AI 在对话里能 `check_mcp_status` 诊断、能 `read_skill` 读技能，但**不能代用户配置 MCP**——用户说"把这个仓库接上"时，AI 只能引导他去设置页自己填。
- **改动后**：用户把 MCP 仓库/URL 交给 AI，AI 读文档提炼配置 → `ask_user` 展示完整 server 配置请求确认 → 用户点"添加" → AI 调 `add_mcp_server` 写入 `.env` + 清缓存 → 下轮原生 MCP 工具装入。删/停用同理。全程对话，不切设置页。

## 二、目标

1. 新增 4 个 @tool：`list_mcp_servers`（只读）、`add_mcp_server`、`remove_mcp_server`、`disable_mcp_server`。
2. 抽 `save_mcp_servers(servers) -> dict` 共用函数：`POST /api/mcp/servers/save` 路由与 `add/remove/disable` @tool 共用，校验/掩码/落盘/清缓存逻辑单一真源。
3. 三个写操作都走 `ask_user` 授权：add/disable 一次确认，remove 二次确认；ask_user 题面展示完整 server 配置（含 command）。
4. add 保存后复用路由预热握手，回告 `[MCP_ADDED]` / `[MCP_ADDED but UNREACHABLE]`；失败引导走 006 的 `check_mcp_status` 诊断。
5. system.md 同步：工具清单+条数、新增硬规则（add/remove/disable 必须 ask_user、参数来源走读文档提炼、生效下轮）。
6. **不做**：skill 聊天安装（008）、plugin 聊天安装（009）、command 白名单、本轮热加载。

## 三、方案设计

### 3.1 共用写入函数

把 `save_mcp_servers_route`（settings.py:435）的校验+落盘+清缓存逻辑抽成 `save_mcp_servers(servers: list[dict]) -> dict`：
- 输入：完整 server 列表（与路由同 schema）。
- 校验：name 必填/不重名、stdio 需 command、http 需 http(s) url（沿用现有逻辑）。
- `_unmask_mcp_headers` 保鉴权 token。
- `_save_env_updates({"MCP_SERVERS": ...})` + `get_settings.cache_clear` + `reset_mcp_cache` + `reset_agent_cache`。
- 预热握手 `get_mcp_tools`（失败不阻塞）。
- 返回 `{"ok": bool, "error"?: str, "mcp_servers": [...], "mcp_status": [...]}`。
- 路由改为调此函数（行为不变）；@tool 也调此函数。

### 3.2 四个 @tool

**`list_mcp_servers() -> str`**：返回当前 `.env` MCP_SERVERS 列表 + 各自连通状态（包装 `mcp_servers_status` + `_mask_mcp_headers`）。只读，无需 ask_user。

**`add_mcp_server(name, transport, url="", command="", args="", headers="") -> str`**：
- 先 `list_mcp_servers` 查重名（重名返回 `[MCP_DUPLICATE]` 引导改用 disable/或先 remove）。
- 调 `save_mcp_servers(现有 + 新 entry)`。
- 按预热结果回 `[MCP_ADDED] name=X 工具数=N` 或 `[MCP_ADDED but UNREACHABLE] name=X 握手失败：…，用 check_mcp_status 诊断`。

**`remove_mcp_server(name) -> str`**：调 `save_mcp_servers(过滤掉 name)`。回 `[MCP_REMOVED] name=X`。

**`disable_mcp_server(name) -> str`**：调 `save_mcp_servers(标 disabled=true)`。回 `[MCP_DISABLED] name=X（下轮不装入工具）`。

### 3.3 ask_user 授权闭环

流程（add 为例）：
1. AI 读用户给的仓库/URL 文档 → 提炼 name/transport/url-or-command/args/headers。
2. AI 调 `ask_user(question=<展示完整配置的中文题面>, options=["添加", "暂不"])`。
3. 用户点"添加" → AI 调 `add_mcp_server(...)`。
4. 工具回告 → AI 转述用户（"已添加 firecrawl，3 个工具已装入，下条消息生效"）。
remove：`ask_user("确认删除「X」？此操作不可恢复。", ["删除","取消"])`。disable：`ask_user("要停用「X」吗？", ["停用","取消"])`。超时=暂不/取消。

### 3.4 参数 schema（Q11）

- `name: str`（必填）
- `transport: str`（"streamable_http" | "stdio"，必填）
- `url: str`（http 型必填，http(s):// 开头）
- `command: str`（stdio 型必填，绝对路径）
- `args: str`（stdio 可选，**空格分隔字符串**，内部 split 成 list）
- `headers: str`（可选，**JSON 字符串**，内部 json.loads）

### 3.5 system.md 契约同步

- 工具清单加 4 个（总数 +4，同步 AGENTS.md/README/docs/02 的工具数与基线计数测试）。
- 新增硬规则：`add_mcp_server/remove_mcp_server/disable_mcp_server` 必须先 `ask_user` 确认（remove 二次确认）；ask_user 题面必须展示完整 server 配置；参数来源走读仓库文档自提炼，不得让用户口述全部字段；加完告知"下条消息生效"。
