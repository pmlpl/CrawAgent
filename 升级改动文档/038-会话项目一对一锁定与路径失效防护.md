## 〇、价值

- **改动前**：① 会话可随时换绑项目，一个会话的产物散落多个文件夹——真机实测（会话 372fa1d32874）换绑后 agent 自己都要向用户解释「下载落在了 test_proj_smoke2（与上次 Desktop\test 不同）」。② 用户删除已绑定的文件夹后：save_to_file / download_social_media / download_images 三处 `mkdir(parents=True, exist_ok=True)` **静默重建目录照写不误**（违背用户"不想要该路径"的意图）；脚本报 `[WinError 267] 目录名称无效` 看不懂；前端提示条只显示字符串从不查磁盘，用户无从发现路径已失效。
- **改动后**：① 一个会话只认一个项目，绑定即锁定（选错 = 新建会话），产物归属永远清晰。② 文件夹被删后 AI 明确报「项目文件夹已不存在」的人话错误、不重建不写入；提示条警示标注、历史菜单失效项标灰——一眼看出该恢复文件夹或新建会话。

## 一、背景与问题

1. **换绑导致产物散落**：035 的 POST /api/sessions/{id}/work-dir 幂等覆盖设计 + 037 历史菜单把"切换"做成一键操作。指挥官 2026-10-01 裁决：**一个会话只允许一个项目，会话内不可切换**。
2. **路径失效无防护**（2026-10-01 排查确认）：file_tool.py:125 / social_tool.py:120 / download_images.py:164 三处 mkdir 静默重建；script_tool/runner.py `_resolve_script_cwd` 返回已删除路径 → subprocess 抛 FileNotFoundError 被 except 兜成不人话的 `[ERROR] ...`；前端 workdir-bar（ChatPage.vue）的 `chat.workDir` 来自 meta.db 字符串，无存在性检查。
3. 037 刚修复的 append-only 历史表（commit c027be5，`work_dir_history` 表）**必须保留**——本变更把历史菜单用途从「切换」反转为「新会话快速初始化」，历史列表正是为它服务的。

## 二、目标

1. **1:1 锁定**：会话已有非空绑定时，POST work-dir 一律拒绝换绑（含清除），返回人话错误；绑定同一路径（规范化后相同）幂等放行。
2. **历史菜单用途反转**：未绑定会话 → 提示条显示「未选择项目」弱化态，箭头弹菜单 = 历史项目一键绑 + 打开新项目（**移除「清除项目」**）；已绑定会话 → 提示条显示路径，箭头弹只读卡片（路径 + 状态，无操作项）。
3. **路径失效防护（写产物四链路）**：save_to_file / download_social_media / download_images / run_custom_script 在落盘前检查「work_dir 已绑定但目录不存在」→ 返回人话错误，不 mkdir、不写入。
4. **前端失效可见**：提示条警示色 + 「文件夹已不存在」标注；历史菜单失效项标灰（点击仍允许——主动重建）。
5. **不做**：失效自动解绑；文件夹移动检测（只查 exists，不查重命名/挪走后原路径出现同名目录）；删除确认弹窗；039 的会话文件夹（另立规格）。

## 三、方案设计

### 3.1 后端锁定守卫（meta_store.set_work_dir）

- set_work_dir 入口处：读旧绑定（get_work_dir），旧值非空且 ≠ 新值（`os.path.normcase(os.path.normpath(...))` 比较消 Windows 大小写/斜杠差异）→ 抛自定义异常（如 `WorkDirLockedError`），message 为人话：「该会话已绑定项目 <旧路径>，一个会话只支持一个项目。如需使用其他文件夹请新建会话。」
- 路由层 except 捕获 → `{ok: False, error: <message>}`（沿用现有错误通道）；`WorkDirLockedError` 与 mkdir OSError 分开判，错误文案不同。
- 同路径幂等重绑放行：仍刷 work_dir_history 的 last_used（常用项目置顶，无害且有益）。
- 换绑被拒时不写任何表（session_titles 与 work_dir_history 均不动）。
- **c027be5 的 append-only 历史写入逻辑保持原样**。

### 3.2 工具层失效检查（session_dir 新增共用 helper）

- session_dir.py 新增 `work_dir_unavailable() -> str`：当前会话 work_dir 非空（`current_work_dir()`）且 `Path(work_dir).exists()` 为 False → 返回人话错误串；否则返回空串。
  - 错误串：`项目文件夹 <路径> 已不存在（可能被删除或移动）。请恢复该文件夹，或新建会话重新选择项目。本次未写入任何文件。`
- 四个工具开头统一调用，非空即返回错误（不抛异常，走工具结果通道让 agent 转告用户）：
  - file_tool.save_to_file → `Save failed: <错误串>`
  - social_tool.download_social_media → error dict（json.dumps，与现有错误格式一致）
  - download_images → 同上
  - script_tool/runner.run_custom_script → `[ERROR] 项目文件夹 <路径> 已不存在，脚本无法运行。请恢复文件夹或新建会话。`
- 检查时机 = 工具调用时现查（不缓存，删了又建回来自然恢复）。
- **未绑定 work_dir 的默认落点行为完全不变**（output/downloads 由项目自身保证存在，不属于本变更范围）。

### 3.3 历史端点带存在性标注

- `GET /api/sessions/work-dirs/history` 返回从 `{work_dirs: [str]}` 改为 `{work_dirs: [{path: str, exists: bool}]}`——一次请求同时拿路径与存在性，避免前端逐项探测。
- `GET /api/sessions/{id}/work-dir` 响应加 `exists: bool`（path 为空时 exists 恒 true/无意义，前端只在 workDir 非空时消费）。
- **前端 037 的 8 个历史菜单 vitest 用例依赖旧结构，必须同步改写**。

### 3.4 前端（ChatPage.vue + useChat.js）

- **未绑定会话**：`v-if="chat.workDir"` 改为恒渲染提示条；workDir 为空时弱化样式显示「未选择项目 · 点箭头选择」，箭头弹菜单（历史项一键绑 + 打开新项目）——补上 037 的交互缺口（未绑定时历史菜单无入口）。
- **已绑定会话**：提示条显示路径；箭头弹只读卡片（路径 + 存在状态标注，无操作项）。锁定后前端不再提供任何换绑/清除入口。
- **失效标注**：workDir 非空且 exists=false → wd-value 追加「（文件夹已不存在）」+ danger 色；历史菜单 exists=false 的项标灰 + 同款标注，点击仍触发绑定（用户主动重建）。
- 切会话/绑定成功后刷新 exists（GET work-dir 或绑定响应带回）。

### 3.5 测试

- 后端：锁定守卫（换绑拒绝/同路径幂等放行/清除拒绝/新会话自由绑定/错误文案人话/被拒不写历史表）；失效检查四链路（work_dir 已删 → 人话错误 + 目录不被重建 + 文件不落盘）；history 端点新结构含 exists。
- 前端：未绑定提示条与菜单、已绑定只读卡片、失效标注渲染、历史项失效标灰、绑定后锁定态。
- 基线：**738 pytest + 76 vitest** 起算同步计数。

## 八、实施记录（2026-10-01）

### 怎么做到的（人话版）

两块防护一批落地：

1. **会话↔项目 1:1 锁定**：`meta_store.set_work_dir` 入口先读旧绑定——旧值非空且新值不同（`normcase+normpath` 规范化比较，Windows 大小写/反斜杠差异消掉）→ 抛 `WorkDirLockedError`，文案含旧路径 + 新建会话指引；旧值非空且新值为空（清除）同样拒绝，堵死「清除再绑别的」绕过。同路径幂等重绑放行且照常刷 `work_dir_history.last_used`（常用项目置顶）。被拒时**不写任何表、不建目录**（锁定判定先于 mkdir）。路由层 `WorkDirLockedError` 与 mkdir `OSError` 分开捕获，前者原样透传人话文案，后者报「文件夹创建失败」。

### 说明（与规格偏差）

- **download_images 错误格式取 JSON dict**：规格 §3.2 标「同上」（指 download_social_media 的 error dict），而该工具既有错误通道是纯文本。按规格字面取 JSON dict——`{"error": ...}` 中无 path 字段，`extract_media` 解析时 JSON 分支查 `downloaded` 键失败自然落空，不影响 012 内联播放链路（已核对 media.py）。
- **ChatComposer 选择项目按钮一并锁定**：规格 §四 文件清单未列 ChatComposer.vue，但 §3.4 硬性要求「锁定后前端不再提供任何换绑/清除入口」，该按钮 tooltip 原文案「点击更换」即换绑入口。处理为已绑定后点击 no-op + tooltip「已锁定 · 如需更换请新建会话」（未绑定时行为不变）。
- **useChat 删除 clearWorkDir()**：清除入口随锁定移除后该函数无调用方（全仓 grep 确认仅 ChatPage 一处使用，已同步删除），避免留下能绕过前端 UI 的空串绑定快捷函数。
- **GET /api/history 的 work_dir 回读不改**：存在性刷新走规格 §3.4 给的「GET work-dir」路径（loadHistory 后调 refreshWorkDirExists），不动 /api/history 响应结构。
- **绑定成功后 workDirExists 置 true 不查磁盘**：set_work_dir 的 mkdir(exist_ok=True) 通过即意味着目录存在，无需再发请求。
- 本变更已随本 commit 入库（代码与文档同批）。
