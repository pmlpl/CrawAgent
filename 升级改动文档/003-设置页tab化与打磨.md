## 〇、价值

## 一、背景与问题

设置页是"功能长了再塞"堆出来的：生态相关三卡平铺、「更多」空占位、思考开关混在界面卡里。指挥官对三个维度不满：布局（无导航）、视觉（密度与观感）、交互（反馈弱）——经 grilling 拍板 Q1=A/C/D、Q2=四页 tab、Q3=暴露既有后端设置，走 to-spec/to-tickets 流程拆四票实施。

## 二、目标

1. tab 化信息架构 + 按页签拆区块组件（prefactor，功能零损失）。
2. 高级页：抓取超时/请求间隔、产物与下载目录（**可编辑存放位置**，保存即生效）、三类保留天数与两类容量上限。
3. 视觉：tab 栏分段式控件、毛玻璃可读性规则、按钮尺寸归一。
4. 交互：保存反馈分级（绿/红条）、生态区提示去重、危险操作确认、加载态防连点。
5. **不做**：「更多」占位兑现（调度策略/白黑名单/导出备份）、主题切换进设置页、Pinia、WebUI 鉴权。

## 三、方案设计

- **组件结构**：外壳只做页签表 + v-show 面板 + 一次性数据加载；四个区块组件各自从模块级单例组合式（useSettings/useBg）取状态，无 props。
- **样式隔离**：共享样式抽到 components/settings/settings.css，**全部规则挂 `.settings-page` 前缀**——文件经 JS import 全局生效，input/select 等元素选择器不加前缀会泄漏到聊天页。
- **设置读写**：只扩一条缝——GET/POST /api/settings 的快照与保存字段，服务端范围校验 + 沿用 .env 回写通道；目录类保存时解析绝对路径并当场建目录。
- **生效语义**：工具层每次调用现读 get_settings()（无缓存），所以抓取参数、产物目录**保存即生效**；保留清理策略在下次启动清理时应用。

## 八、实施记录（2026-09-07）

### 怎么做的（人话版）

**重构的窍门是"先让改动变容易"**：T1 只做搬家——把 962 行大文件按页签拆成四个小文件，一根手指都不改功能。搬完之后 T2-T4 每个改动都只碰一个小文件，改错也好回滚。状态层没动：useSettings 是全站单例，四个组件各自去拿同一份，所以页签切换不丢表单内容。

**这次战役里真正值得记住的是四颗雷和一个姿势**：

1. **"null" 启动级雷（两颗同款）**。给"不清理/不设上限"这种可空设置设计 .env 表示法时，第一直觉是写 `null`——实测发现 pydantic-settings 默认把 `null` 当普通字符串，`int` 类型字段解析直接抛异常，**后端下次启动整个起不来**。解法：给 Settings 配置 `env_parse_none_str="null"`，让这个字符串被认成"空值"。第二颗同款是"抓取超时清空后保存"会落盘字符串 `None`——解法是必填数值清空一律服务端拒绝（"不能为空"）。两颗都被 TestClient 测试先行抓住，没流进真机。
2. **残留进程假象**。用测试脚手架起临时后端做冒烟，脚手架报告"服务已停止"但 uvicorn 孤儿进程还占着端口；下一次启动的新服务绑定失败悄然退出，**冒烟请求全打在旧进程上**——新字段全是 None，差点误判代码有 bug。解法与纪律：冒烟前先清端口、结果与预期不符时第一反应查"是不是旧进程在应答"。此坑已入长期记忆。
3. **静态资源 404 的姿势问题**。直接用 uvicorn 起 app 对象时 `/assets` 全 404——静态目录挂载写在 `main()` 里，只有 `python -m crawagent.web.server` 方式启动才会挂载。不是 bug，是启动姿势；冒烟必须走模块方式。
4. **CSS 泄漏**。设置页样式抽成全局文件后，裸的 `input {}` 会污染聊天页输入框——全部规则挂 `.settings-page` 前缀根治。
5. **"停用"竖排**。表格操作列宽度不够，按钮被压缩后中文逐字换行——按钮基类加 `white-space: nowrap` 根治，而非给那一个按钮打补丁。

**code-review 双轴审查**（Standards + Spec 并行子代理）又抓到一颗真雷（清空超时落盘 `None`）和一处新 UI 的反馈漏洞（11 处旧代码路径绕过分级导致失败显示成绿色），均已修复；一条"MCP 移除无确认"经核实是误报（confirm 在组合式函数里）。
