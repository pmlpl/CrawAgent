# 04 · 扩展能力

> 分布式爬虫、Android 逆向、App 抓包——CrawAgent 的进阶场景。

## 分布式爬虫

### 适用场景

- 单机爬不完的超大规模任务（数千 URL +）
- 需要多机协同处理（多台机器跑 worker）
- 需要任务持久化 + 崩溃恢复（worker 挂了任务不丢）

### 启用方式

```bash
# 1. 装分布式依赖
uv sync --extra dist

# 2. .env 开启
# DIST_ENABLED=true
# CHECKPOINT_BACKEND=redis
# REDIS_URL=redis://127.0.0.1:6379/0
```

启动后端：

```bash
uv run crawagent start
```

启动时会自动：

1. 先尝试连已有 Redis（`REDIS_URL`）
2. 连不上 → 找系统 `redis-server` 二进制
3. 系统没装 → Windows 自动下载 portable Redis 到 `data/redis/`（首次约 5MB）
4. 下载失败 → 提示用户手动装或指向远程 Redis

启动独立 worker（多机部署时）：

```bash
uv run crawagent-dist-worker
```

### 任务流

```
提交任务 POST /api/dist/tasks
   ↓
入队 Redis ZSET（score=priority*1e13+ts_ms）
   ↓
Worker BZPOPMIN 原子领取
   ↓
claim_task 写 running SET + 心跳 TTL
   ↓
执行 run_turn（emit 回调推 pubsub）
   ↓
finish_task / 崩溃 requeue_stale_running 重投
   ↓
事件流 /ws/dist/{task_id}（done/error 永不丢）
```

### REST + WS API

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/dist/tasks` | POST | 提交任务（session_id + text + priority） |
| `/api/dist/tasks` | GET | 列出任务（status 筛选） |
| `/api/dist/tasks/{id}` | GET | 查任务详情 |
| `/api/dist/tasks/{id}` | DELETE | 取消任务 |
| `/api/dist/workers` | GET | 列出在线 worker |
| `/ws/dist/{task_id}` | WS | 实时事件流（断线重放） |

### Redis 数据结构

| Key | 类型 | 用途 |
|------|------|------|
| `crawagent:tasks` | ZSET | 待领取队列（score=priority*1e13+ts_ms） |
| `crawagent:task:{tid}` | HASH | 任务元数据 |
| `cawagent:task:{tid}:events` | LIST | 事件日志（LTRIM cap 1000） |
| `crawagent:task:events:{tid}` | PubSub | 实时事件推送 |
| `crawagent:tasks:running` | SET | 正在跑的 task_id |
| `crawagent:workers` | SET | 在线 worker 集合 |
| `crawagent:worker:{wid}` | HASH | worker 状态（EX ttl 30s 心跳） |

### 崩溃恢复

Worker 心跳 TTL 30s，挂掉后任务标记为 stale，由后台 sweep 线程扫描并重投到队列。任务永不丢失。

### 向后兼容

不设 `DIST_ENABLED` / `CHECKPOINT_BACKEND` 时，系统仍用 SQLite checkpointer 单进程跑，前端对话与侧栏 sessions 列表完全正常。**零侵入热路径**——分布式逻辑不污染主对话循环。

## Android 逆向

### 适用场景

- App 加密接口逆向（定位加密函数、dump SO、绕过 SSL pinning）
- 抓取 App 内明文通信（配合 MCP 抓包链路）

### 前置条件

1. Android 设备已 root + 开 USB 调试
2. 安装 frida-server 到设备（与本地 frida 版本匹配）
3. 本地装 frida CLI：`pip install frida frida-tools`（不写入主依赖避免冲突）
4. ADB 可用（系统 PATH 或 `adb` 命令能跑）

### 工作流（system.md 内置 Workflow）

```
Step 0: list_adb_devices() 确认设备在线 + 已 root
Step 1: install_apk / push_file（frida-server 推到设备）
Step 2: frida_hook_function 定位加密函数
Step 3: frida_bypass_ssl_pinning → 立即走 MCP Capture Workflow 抓明文
Step 4: frida_dump_so（native SO 逆向，配合 IDA）
```

### 工具说明

| 工具 | 用途 | 备注 |
|------|------|------|
| `list_adb_devices` | 列在线设备 | 返回 serial + 状态 |
| `install_apk` | 装 APK 到设备 | 路径本地或 URL |
| `push_file` | 推文件到设备 | 用于推 frida-server |
| `frida_hook_function` | hook 指定函数 | 定位加密逻辑 |
| `frida_dump_so` | dump native SO | 配合 IDA 静态分析 |
| `frida_bypass_ssl_pinning` | 绕过 SSL pinning | 内置社区脚本 |

工具按需调用 frida CLI（subprocess），调用时检查二进制存在性并给安装提示。frida 不在主依赖里，避免其 `websockets` 约束与主环境冲突。

## App 抓包

### 用已有 MCP 链路

App 抓包**不另建工具**，复用 anything-analyzer MCP server 提供的 30 个抓包分析工具：

- `navigate` 启动抓包会话
- `filter_requests` 筛选目标请求
- `wait_capture_ready` 等待会话就绪（CrawAgent 工具层）
- 各类分析工具解码 / 还原 / 比对

### 典型链路

```
Android 逆向定位加密点
   ↓
frida_bypass_ssl_pinning 绕过证书校验
   ↓
wait_capture_ready 等抓包会话就绪
   ↓
filter_requests 筛选目标接口
   ↓
解析 / 还原 / 落库
```

详见技能包中的 MCP Capture Workflow（`read_skill(name)` 调用）。
