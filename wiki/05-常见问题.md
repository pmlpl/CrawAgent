# 05 · 常见问题

> FAQ + 故障排查指引。先看这里再翻日志。

## 一、安装与启动

### Q1：`uv sync` 报依赖冲突

**A**：最常见是 `frida-tools` 的 `websockets` 约束与主环境冲突。frida 已不写入主依赖，按需手动装：

```bash
pip install frida frida-tools
```

不要把 frida 加进 `pyproject.toml`。

### Q2：启动报 `langgraph-checkpoint-redis` 找不到

**A**：版本约束已修正为 `>=0.5.2`（旧约束 `>=2.0.0` 不存在该版本）。分布式模式才需要：

```bash
uv sync --extra dist
```

### Q3：`uv run crawagent start` 不弹浏览器

**A**：v2026.09 起改为不自动弹浏览器。两种打开方式：

1. **前端按钮**：WebUI 设置页或聊天页的"打开应用"按钮一键启动
2. **手动访问**：浏览器输入 `http://127.0.0.1:8006`

设 `CRAWAGENT_HOST=0.0.0.0` 时也不弹（容器/局域网监听场景）。如需强制禁止：`CRAWAGENT_NO_OPEN=1`。

### Q4：嵌入 Redis 启动失败

**A**：检查顺序：

1. 系统是否已有 Redis 在跑（端口 6379 占用）→ 设 `REDIS_URL` 指向它
2. 系统没装 redis-server → 检查 `data/redis/` 是否下载成功
3. 离线环境 → 手动装 Redis 或指向远程 Redis
4. 看启动日志 `[redis]` 开头行，有具体错误

非分布式模式不需要 Redis，直接忽略。

### Q5：Playwright 报"浏览器未安装"

**A**：

```bash
uv run playwright install chromium
```

`browse_and_crawl` / `crawl4ai_deep_crawl` / `browser_use_navigate` 都需要。

## 二、对话与工具

### Q6：Agent 不调工具

**A**：正常。多数对话轮次零工具调用——问候、概念问题、策略讨论、从历史里选序号都不触发。只有"URL + 动作动词"才进工具循环。拿不准时 Agent 会先文字追问。

### Q7：Agent 死循环

**A**：`ScriptForcerMiddleware` 应该会拦——连续 3 次失败强制写自定义脚本，30 次总调用强制输出答案。如果还在循环，看日志 `crawagent/graph/script_forcer.py` 的计数是否生效。

### Q8：列表页抓不到条目（<5 条）

**A**：静态 HTML 是 JS 渲染的。系统应自动切 `browse_and_crawl` 重抓。如果没切，检查 `extract_list` 返回条目数与置信度。JS 分页（加载更多/无限滚动）必须 `run_custom_script`。

### Q9：详情页提取置信度低

**A**：看到 `[LOW CONFIDENCE]` 标记时系统应自动切浏览器重抓。如果没切，手动让 Agent 用 `browse_and_crawl` 同 URL 重抓后再提取。

### Q10：图片 URL 抓不到（懒加载）

**A**：图片懒加载站点必须用浏览器渲染抓取真实 URL。系统会自动识别并切 `browse_and_crawl`。`save_executor` 检测到数据含图片 URL 字段时自动下载。

### Q11：SPA 4xx 页面被当成失败

**A**：v2026.09 起，Playwright 遇 4xx 时会等待客户端路由完成，若渲染内容有效（>500 字符且 title 不含"404"）则覆盖状态为 200。仍有问题检查渲染内容长度。

### Q12：登录墙 / Cookie 过期 / VIP / 401 / 403

**A**：Agent 遇认证墙应立即停止换工具重试（必撞同一堵墙），告知用户需要什么凭据。手动配：

- 全局 Cookie（如 B站）：`.env BILIBILI_COOKIE`
- 站点级 Cookie（如微信读书）：WebUI「站点档案」页或 `save_site_profile(cookies=...)`

### Q13：批量抓取太慢

**A**：BATCH-FIRST 硬规则——抓多个同类条目必须写一个带循环的 `run_custom_script`，禁止逐条调工具。30 章/50 张壁纸一个脚本搞定，禁止 50 次工具调用。

## 三、分布式

### Q14：任务一直 pending 不被领取

**A**：

1. 检查是否有 worker 在线：`GET /api/dist/workers`
2. 没有 worker → 启动：`uv run crawagent-dist-worker`
3. Worker 在线但不领 → 看心跳 TTL（30s），可能 worker 卡死，等 sweep 线程重投
4. 看 `crawagent:tasks` ZSET 是否有数据

### Q15：任务状态卡 running 不结束

**A**：worker 挂了。后台 sweep 线程会扫描 stale 任务（心跳过期）并重投。检查 `dist_task_sweep_interval` 配置（默认 60s）。

### Q16：事件流断线后丢消息

**A**：不应该丢。事件日志 append 到 Redis LIST（LTRIM cap 1000），断线重连按 cursor 从 0 重放，`done` / `error` 收尾事件永不丢。看 `/ws/dist/{task_id}` 重连逻辑。

## 四、性能与成本

### Q17：LLM token 消耗高

**A**：

- 历史 token 裁剪：`HISTORY_MAX_TOKENS`（默认 8000）
- 工具结果裁剪：`TOOL_RESULT_MAX_CHARS`（默认 500）
- prompt cache：System Prompt 纯静态保证命中
- 半水位淘汰：超限一次性淘汰到 max/2，窗口固定
- 上下文 token 用量通过 API 暴露，前端可看

### Q18：缓存命中率低

**A**：旧滑动窗口方案实测 37.5%。v2026.08 起改用半水位淘汰 + 强制消息追加末尾（不打碎缓存前缀）。看 `observability/metrics.py` 的真实数据，langchain-openai 只映射 `cache_read`，从 `token_usage` 兜底。

## 五、数据与持久化

### Q19：会话重启后没了

**A**：检查 `data/sessions.db` 是否存在。分布式模式检查 `CHECKPOINT_BACKEND=redis` 与 Redis 连通。thread_id 必须可靠传递（v2026.09 起用 ContextVar `ctx_session_id`）。

### Q20：临时文件堆积

**A**：临时文件集中存 `data/_tmp/`（不进系统 `%TEMP%`）。>1h 自动清理（启动时扫描）。正常执行完成直接删除（不进回收站）。

### Q21：output/ 和 downloads/ 无限增长

**A**：目前无清理策略（P2 观察项）。手动清理或写 cron。

## 六、报错排查通用流程

1. **看启动日志**：`uv run crawagent start` 控制台输出，`[redis]` / `[dist]` / `[mcp]` 开头行
2. **看运行日志**：`logs/` 目录，按 session 归档
3. **看会话错误**：`data/meta.db` 的 `session_errors` 表
4. **看测试**：`uv run pytest tests/ -v`
5. **看冒烟**：`uv run python -c "from crawagent.graph.agent import SYSTEM_PROMPT; from crawagent.web.server import app; print('OK')"`
6. **看 LangSmith**：配 `LANGSMITH_TRACING=true` 后看链路追踪
