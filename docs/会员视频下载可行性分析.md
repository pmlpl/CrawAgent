# 会员（VIP）视频下载可行性分析

> 生成时间：2026-08-02
> 目的：说明"爬取主流视频平台会员视频"在技术链路、合规边界、项目现状三方面的完整图景
> 结论先行：**元数据可抓，视频流被 DRM 保护；合规前提 + 技术缺口见下文**

## 0. 合规前提（必须满足）

以下内容仅在**你自己已合法拥有对应 VIP 会员权限**、且**仅用于个人合理使用**的前提下讨论；
任何绕过付费墙、破解 DRM 加密、以及下载后对外分发/售卖的行为，均属侵权，项目不实现、不协助。

- 腾讯视频 / 优酷的 VIP 内容受《著作权法》保护，且套用**技术保护措施（DRM）**
- 破解技术保护措施本身即违法（《著作权法》第 49 条），与是否拥有账号无关
- 平台服务条款通常禁止将流媒体导出为本地文件；**合法下载路径 = 平台官方缓存/下载功能**

## 1. 技术链路拆解

爬取会员视频的完整链路，无论哪个平台，都是 5 步：

```
① 登录态（VIP cookie）
② 取流接口（play_url：需视频 ID + 签名参数）
③ 签名计算（由平台 JS 运行时生成，随时失效）
④ 流媒体解密（DRM / 加密 m3u8 / TSD 分片）
⑤ 下载拼接（解密后的分片 → mp4）
```

### 各环节与项目现状对照

| 环节 | 需要什么 | 项目现状 | 缺口 |
|------|---------|---------|------|
| ① 登录态 | VIP 账号 cookie | ✅ 已有（P8 `login_interactive` 手动登录持久化） | 无 |
| ② 取流接口 | 视频 ID（vid/showid）+ 签名 URL | ⚠️ 部分：P9 `harvest_api` 可捕获页面已下发的接口 | 取流接口是否公开取决于平台策略 |
| ③ 签名计算 | a_bogus / sign / tsign 等 | ✅ P9"浏览器即签名机"思路可覆盖（拦截浏览器真实请求） | 需针对平台调 API 特征 |
| ④ DRM 解密 | 解密密钥 + 算法（Widevine / FairPlay / 自研加密） | ❌ **无** | **核心硬缺口** |
| ⑤ 下载拼接 | 解密后的分片 + ffmpeg | ✅ 部分（MediaDownloader + yt-dlp） | 解密后即可复用 |

## 2. 两个平台的实测情况（2026-08-02）

| 平台 | 页面 API 捕获 | 结构化数据 | 视频流直链 | DRM 情况 |
|------|-------------|-----------|-----------|---------|
| 腾讯视频 | ✅ 41 条/页（tRPC 接口） | ✅ 72 条（剧集/追剧/评分） | ❌ 未下发 | TSD 分片加密，取流需 sign+cookie |
| 优酷 | ✅ 19 条/页 | ✅ 46 条（评分/剧集元数据） | ❌ 未下发 | m3u8 加密，需解密钥 |

结论：**①②③ 的自动化已有基础；④ DRM 解密是人工/工具无法绕过且违法的环节。**

## 3. 合法路线推荐（替代"抓取会员视频"）

如果目标是"下载自己喜欢看的 VIP 内容"，按优先级：

1. **平台官方下载**：腾讯视频 / 优酷 App 或客户端的"离线缓存/下载"功能（VIP 权益内合法）
2. **会员缓存目录提取**：平台缓存到本地的文件（部分平台缓存为加密格式，仅官方播放器可播放；提取需遵守条款）
3. **元数据采集**：用本项目 P9 `harvest_api` 抓剧集列表、评分、评论、热度做数据分析（完全合法，已验证可行）
4. **公开免费内容**：平台免费专区 / 公开视频，yt-dlp 可尝试下载（腾讯部分免费内容支持，成功率依赖平台加密策略）

## 4. 如果目标是"技术研究"而非"内容获取"

对 DRM / 签名机制的研究建议在**合法授权环境**下进行：
- 使用平台开放平台（OpenAPI）授权接口（如有）
- 使用自有版权内容做加密传输研究
- 关注学术/安全研究场景的正规授权

## 5. 结论

- **能做的**：VIP 站点的登录态、元数据、签名 API 捕获、公开免费内容下载——项目已具备且实测通过
- **不能做的**：DRM 解密、绕过付费墙——技术上存在且**不应实现**（违法）
- **建议**：以"元数据采集 + 公开内容"作为这类平台的训练方向；VIP 内容走官方渠道
