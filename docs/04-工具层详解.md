# 04 · 工具层详解

21 个 LangChain `@tool` 函数（20 个内置 + 插件提供），内置的在 `crawagent/tools/`，插件的在 `plugins/<name>/tools/`。docstring 即 LLM 看到的工具规范——LLM 靠它决定何时调用、怎么传参。

## 工具全景

### 基础爬取

| 工具 | 功能 | 实现 |
|------|------|------|
| `crawl_webpage(url)` | 静态 HTTP 抓取 HTML | requests + fake-useragent |
| `browse_and_crawl(url, task)` | 浏览器渲染动态页 | Playwright；含番茄小说 PUA 字体解密 |

### 自定义脚本（兜底武器）

| 工具 | 功能 | 实现 |
|------|------|------|
| `run_custom_script(code, timeout)` | Agent 现场写 Python 脚本执行，专治内置工具搞不定的站 | 预导入 requests/bs4/json/re/os/Path 等；stdout 返回给 LLM |

### 内容提取

| 工具 | 功能 | 实现 |
|------|------|------|
| `extract_content(html, focus)` | 详情页提取标题 + 正文，输出 **Markdown**（保留标题层级/围栏代码块含语言标注/列表/引用/表格/行内链接与行内代码） | html2text 按 DOM 树整体转换 + BS4/lxml 定位主内容（`<article>`→`<main>`→`<body>`）；空白归一化分块去重；内置置信度评分，<60 加 `[LOW CONFIDENCE]` 标记。注意：**不再输出 Links 列表**，需要链接请用 `extract_list` |
| `extract_list(html, url)` | 列表页提取条目（title + url） | 混合策略：正则 → LLM 兜底 → DOM 深度；自动过滤导航/页脚链接 |

### 存储与查询

| 工具 | 功能 | 实现 |
|------|------|------|
| `save_record(url, title, content, extra_data)` | 存入 SQLite | data/crawagent.db |
| `list_crawled_resources(platform, keyword, limit)` | 查历史抓取记录 | SQL 查询，避免重复爬取 |
| `save_to_file(filename, content, subdir)` | 存本地文件 | md/txt/json → output/ |

### 社媒（抖音 / B站）

| 工具 | 功能 | 实现 |
|------|------|------|
| `extract_social_media(url, fields)` | 元数据/评论/媒体 URL | 纯 requests，免登录免 Cookie |
| `download_social_media(url, include, subdir)` | 下载视频/音频/封面/评论 | B站自动合并音视频（需 ffmpeg） |

### 壁纸 / 图片站

| 工具 | 功能 | 实现 |
|------|------|------|
| `extract_wallpaper_list(url, limit, exclude_dynamic)` | 壁纸列表提取 | 处理 CSS background-image 卡片、自动翻页、详情页跳转 |
| `wallpaper_detail(url)` | 单个壁纸详情 | 类型(静态/动态)/分辨率/全部 URL |
| `download_images(urls, subdir, referer)` | 批量下载图片/视频 | 支持防盗链 referer |

### 微信读书

| 工具 | 功能 | 前置条件 |
|------|------|---------|
| `list_weread_chapters(url_or_book_id)` | 章节列表 | weread.qq.com 站点档案配了 Cookie（wr_vid + wr_ssk） |
| `get_weread_chapter(book_v, chapter_uid)` | 章节正文 | 同上 |

### 站点档案（Site Profile）

| 工具 | 功能 |
|------|------|
| `list_site_profiles(origin)` | 查已保存的站点策略；命中则跳过分析直接执行 |
| `save_site_profile(origin, title, strategy, notes, cookies)` | 抓取成功后保存策略供复用；`cookies` 存站点级登录凭据 |

策略值：`crawl_webpage`（静态）/ `browse_and_crawl`（SPA/JS/字体加密）/ `weread_cookie` / `wallpaper` / `social_media` / 自定义。

## 辅助模块（非 @tool）

| 模块 | 功能 | 被谁使用 |
|------|------|---------|
| `confidence.py` | 置信度评分 + `[LOW CONFIDENCE]` 标记生成 | extract_tool |
| `font_decrypt.py` | PUA 码点解密（Source Han Sans 字形匹配） | browse_tool |

## LLM 的工具选择逻辑（SYSTEM_PROMPT 内置规则）

### 何时调工具：TOOL USE JUDGMENT 决策树

多数对话轮次**零工具调用**。只有用户请求包含"可立即执行的动作"才进工具循环：

- **调工具**：URL + 动作动词（crawl/fetch/extract/download/save）、"下载这个视频"、"列出这本书全部章节"、明确查库指令
- **不调工具**：问候/闲聊、概念问题、策略讨论、代码求助、从历史里选序号（用户发"3"选上一轮列出的选项）、对站点的评论
- **默认不调**：拿不准时先文字追问，一次浪费的工具调用比一个澄清问题更糟

### 站点类型路由

- **列表页 vs 详情页**：索引/目录/分类页 → `extract_list`；单篇文章/章节 → `extract_content`
- **列表页降级硬规则**：`extract_list` 返回 < 5 条 → 说明静态 HTML 是 JS 渲染的，切 `browse_and_crawl` 重抓后再提取
- **置信度硬规则**：看到 `[LOW CONFIDENCE]` → 立即 `browse_and_crawl` 同 URL 重抓 → 重新提取
- **社媒直连**：抖音/B站链接跳过 crawl_webpage，直接 `extract_social_media`
- **壁纸站专用**：CSS bg-image 卡片 `extract_list` 抓不到，必须用 `extract_wallpaper_list`
- **微信读书专用**：不用 crawl/browse（会拿到登录页），直接 weread 工具
- **先查档案**：爬新站先 `list_site_profiles(origin)`，命中按保存的策略执行；档案带 script 时直接 `run_custom_script` 执行

### 防失控硬规则

- **3 次失败必写脚本**：同一站连调 3 个内置工具无可用结果 → 必须 `run_custom_script`，不许试第 4 个
- **SPA 空壳即失败**：`crawl_webpage` 返回 <5KB 纯 script 壳 = 失败，不再试 browse，直接写脚本
- **批量优先（BATCH-FIRST）**：抓多个同类条目（30 章/50 张壁纸）必须写**一个**带循环的 `run_custom_script`，禁止逐条调工具
- **工具预算（TOOL BUDGET）**：开工前一句话报计划调用量；单请求超 10 次调用必须改用脚本收敛到 5 次内
- **认证墙即停（AUTH WALL）**：遇到登录/Cookie 过期/VIP/401/403 → 立即停止换工具重试（必撞同一堵墙），告知用户需要什么凭据
- **下载路径（DOWNLOAD PATH）**：媒体文件一律 `downloads/`，仅文本文档 `save_to_file` 落 `output/`
- **禁止猜 API**：不许自行猜测 `/api/*` 内部端点
- **失败不落库**：提取失败/空/乱码时禁止调 save_record / save_to_file
- **跨会话隔离**：聊"本次会话"时不查其他会话的产物；`list_crawled_resources` 默认仅当前会话，`scope="all"` 仅在用户明说"所有历史"时使用
- **静默调用**：工具调用前后不写旁白（"让我试试…"），全部完成后一次性汇总

## 技能扩展（P2-9）

目录约定式技能加载（`crawagent/graph/skills.py`），兼容 Claude/Trae 的 SKILL.md 格式：

```
skills_dirs（.env，分号分隔，默认 "skills"）
  └── <skill-name>/SKILL.md          ← frontmatter(name, description) + 正文
        └── references/*.md          ← 可选，read_skill(name, ref=...) 按需读取
```

- **索引注入**：Agent 构建时把每个技能的 name + description（≤200 字符）拼进
  system prompt 的 AVAILABLE SKILLS 段（当前 7 个技能约 1KB，前缀缓存友好）
- **正文按需**：任务命中时 LLM 调 `read_skill(name)` 读全文（截断 30000 字符），
  渐进披露，不膨胀每轮上下文
- **插件自带技能**：`plugins/<name>/skills/*/SKILL.md` 自动并入索引（见下节）
- **内置技能包**（`skills/`，写入规范见 skills/README.md）：B站 / 抖音 / 壁纸站 /
  微信读书四个站点攻略 + 批量抓取总配方 + run_custom_script 配方库

## 第三方 MCP 接入（P2-9）

`.env` 的 `MCP_SERVERS`（JSON 数组）支持任意多 server；`skills.get_mcp_tools()`
逐 server 连接与缓存：

- **故障隔离**：单个 server 连不上只跳过它自己并打日志，其余 server 照常并入
  工具表；失败的 server 不缓存，下轮自动重试
- **缓存**：成功的 server 按配置指纹（`MCP_SERVERS` 原文）缓存握手结果，进程内
  只握手一次（防重复 asyncio.run 泄漏 SSE 协程）；`reset_mcp_cache()` 强制重连
- **`{project_root}` 占位符**：stdio 的 command/args 里可引用项目 venv 解释器，
  配置随仓库走
- **stdio vs streamable-http**：stdio 型每次工具调用重启一次子进程（fetch 这类
  轻量服务无感；浏览器类可接受）；长驻服务一律 streamable_http/sse

当前接入的三个 server（见 `.env.example` 推荐配置）：

| server | 传输 | 安装方式 | 提供 |
|--------|------|---------|------|
| anything-analyzer（自研） | streamable_http | pnpm dev（内置自动拉起） | 抓包分析 30 工具 |
| fetch（官方 mcp-server-fetch） | stdio | `uv pip install mcp-server-fetch` | `fetch` 网页转 Markdown |
| playwright（微软 @playwright/mcp） | stdio | `npm i -g @playwright/mcp` | 24 个 `browser_*` 工具 |

Windows 踩坑（实测结论，2026-09-05）：

- **不要用 uvx 起 stdio server**：本机 uvx 每次启动都重新下载依赖（缓存不生效），
  initialize 握手必然超时 → 改装进项目 venv 用 `python -m` 直拉
- **不要用 `npx @latest`**：每次 spawn 都查 npm registry；全局安装后直接引用
  `.cmd` 完整路径
- mcp SDK 1.29.1 + anyio 4.14 在 Windows 默认 Proactor 循环下工作正常，无需
  切 SelectorEventLoopPolicy（旧 issue #552 的 workaround 已过时）

## 插件规范（P2-9）

第三方插件统一放项目根 `plugins/`，目录约定：

```
plugins/<plugin-name>/
  plugin.json      ← manifest：name 必填；version/description/author/dependencies 可选
  tools/*.py       ← 工具模块（可选）：模块级 @tool / @register_tool 自动进 Agent 工具表
  skills/*/SKILL.md ← 技能包（可选）：自动进技能索引
  requirements.txt ← pip 依赖清单（可选，仅提示，需手动 uv pip install -r）
  README.md
```

- **发现机制**：`registry.discover_tools()` 第 4 步扫描插件（`_plugin_tool_specs`），
  用 `spec_from_file_location` 以 `crawagent_plugin_<name>_<stem>` 唯一名导入；
  单插件失败只跳过不阻断；与内置工具重名的插件工具被忽略（内置优先）
- **manifest.dependencies**：展示与 ToolSpec.dependencies 透出，`crawagent plugins`
  可查看；缺依赖在插件模块 import 失败时打警告
- **CLI**：
  - `crawagent add-tool <name>` — 从 `crawagent/tools/_template/` 脚手架生成插件包
    （manifest + 工具模块 + 示例技能，全部自动改名替换）
  - `crawagent add-plugin <本地路径|git URL>` — 校验 manifest 后复制/克隆进 plugins/
  - `crawagent plugins` — 列出已装插件与工具/技能数量
- **示例插件**：`plugins/example-rss/`（fetch_rss_feed 工具 + rss-discovery 技能），
  亦是 `add-tool` 的脚手架源
