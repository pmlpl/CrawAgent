## 维度 5：性能隐患

### P0：10 个同步 @tool 在 async 上下文阻塞事件循环

FastAPI + LangGraph 的执行链路是 asyncio 事件循环。LangChain `@tool` 装饰的函数如果是同步 def，框架会在每次调用时跑在线程池 —— 但**默认 ToolNode 不强制 offload**，要靠 `asyncio.to_thread` 显式包。

脚本扫描到的 10 个 @tool 同步 IO 函数：

```
crawagent/tools/crawl_tool.py:55              crawl_webpage
crawagent/tools/download_images.py:153        download_images
crawagent/tools/login_tool.py:456             check_login_status
crawagent/tools/mcp_capture_tool.py:188       wait_capture_ready
crawagent/tools/proxy_tool.py:104             get_proxy
crawagent/tools/script_tool.py:851            run_custom_script
crawagent/tools/video_probe_tool.py:60        probe_video_player
crawagent/tools/weread_tool.py                list_weread_chapters / get_weread_chapter
crawagent/tools/_template/tools/example_tool.py:31  fetch_rss_feed
```

**症状**：并发跑 3-4 个会话 + 任一会话触发 crawl_webpage，整个事件循环被这次请求阻塞 30-60 秒（爬 + 节流）。其它会话的 UI 心跳、SSE 流全部卡死。

**修复路径**：

1. 短期：在 LangGraph ToolNode 配置 `asyncio.to_thread` 自动 offload（langgraph 配置项）
2. 中期：把这 10 个工具改 `async def` + `httpx.AsyncClient`
3. 长期：迁移到 `anyio`/`trio` 统一异步生态

### P2：session 归档/删除同步执行

`web/routers/sessions.py:320` `_archive_session_sync`、`web/routers/sessions.py:395` `_delete_session_sync`：归档要 dump+压缩，删除要拆 checkpoint 文件，都是同步 IO 但被 async router 调用。一次批量删除 N 个会话会阻塞 N 倍时间。

### P3：脚本执行单文件 729 行 + subprocess.run stdin 喂大代码

`script_tool.py:851` `subprocess.run([python], input=full_code)` 把整个用户脚本通过 stdin 喂给子 Python。729 行单文件、单进程同步等结果。脚本超过 ~1MB 时 stdin 缓冲会卡（实际不太可能触发，但路径存在）。

### P4：前端主 chunk 221KB

`web/dist/assets/index-C8IB54OX.js` 221KB（gzip 前）。`marked` + `dompurify` + `pinia` 全在主 bundle。Vue Router 已支持路由懒加载，但 `SettingsPage` 拆成独立 chunk 27KB 没看见 main 拆分记录 —— 可能 marked/dompurify 是首屏必需的（用于 chat markdown 渲染）但应该有按需 import 的空间。

`npm run build` 2.49s 还行，跟 350 测试 68s 比是亮点。

### 6 个 pytest warning 待查

后台 pytest 输出：`350 passed, 6 warnings`。warnings 没收集到内容，建议加 `-W default::DeprecationWarning --tb=short` 看清楚是哪个包在弃用 API 提醒。

## 维度 6：安全隐患

### P2：subprocess.Popen + shell=True（MCP 命令启动）

`crawagent/graph/skills.py:364-366`：

```python
subprocess.Popen(
    cmd, shell=True,
    cwd=cwd,
    ...
)
```

`cmd` 是从 MCP server 配置拼出来的。如果 `.env` 里 `MCP_SERVERS` JSON 数组某条目的 `command` 含 `; rm -rf ~` 这类 payload，shell=True 会执行。当前 `.env` 是用户自己配的，威胁模型是"用户拷了网上来的配置"—— 但 ADR-0003 已经决定"MCP 走无命令白名单"的方向，所以 shell=True 与该决策**直接冲突**，应删。

### P2：file_tool.py 路径 startswith 校验

`crawagent/tools/file_tool.py:40`：

```python
if not str(file_path).startswith(str(base)):
    raise ValueError(f"path escapes project root: {file_path}")
```

两个问题：

1. `base = settings.project_root.resolve()` —— Windows 上 `Path.resolve()` 不解析 symlink（要 `Path.resolve(strict=False)` 也一样），攻击者构造 `output/../secret.txt` 在 `.resolve()` 后会被规范化掉，这个 OK；但 symlink 攻击仍然能跳出（项目根内放个 symlink 指向 `C:\Windows`）
2. startswith 不区分大小写（Windows 路径不敏感）—— `Output/x` vs `output/x` 都能进；如果未来加额外的"白名单子目录"会绕过

**修复**：用 `pathlib.PurePath.is_relative_to()` (Python 3.9+) 或 `os.path.commonpath([base, file_path]) == base`，并显式调用 `Path.resolve(strict=True)` 触发 symlink 检查。

### P3：dist/redis_server.py subprocess.Popen

`crawagent/dist/redis_server.py:117` 起 redis-server 子进程。没有 shell=True，但 cmd 拼接来自 settings —— 如果以后允许用户配 `redis_server_path` 就要做白名单（参考 ADR-0003）。

### P3：cli.py git clone 接 source 字符串

`crawagent/cli.py:207` `git clone --depth 1 <source>` —— source 来自 plugin install 命令行参数。需要确认 CLI 不接 source 参数直接交给 git（git 自己会校验 protocol）。

### P4：script_tool.py 跑任意用户脚本

**by design** —— 这是产品核心能力。但要确认：

- subprocess timeout 一定生效（避免死循环脚本）
