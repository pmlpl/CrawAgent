# 03 · 核心机制

## Agent 执行循环

```
用户输入 (HumanMessage)
    │
    ▼
Agent 节点 (create_agent: LLM + 17 工具 + 双中间件)
    │
    ▼
LLM 返回 tool_calls？──是──> 执行 @tool 函数 ──> ToolMessage 回给 LLM ──┐
    │否                                                                │
    ▼                                                                  │
最终回复（流式输出）<───────────── 循环继续 <──────────────────────────┘
```

- LangChain `create_agent` 内部处理整个 LLM↔工具循环，项目不自建 loop 逻辑
- 每次工具结果返回后 LLM 被重新调用，直到它不再请求工具、直接输出文本
- SYSTEM_PROMPT 内置 **TOOL USE JUDGMENT 决策树**：问候/概念/策略讨论/选序号 → 零工具调用直接回答；URL+动作动词/明确下载指令 → 才进入工具循环。多数对话轮次不产生任何工具调用

### 核心装配代码（`graph/agent.py`）

```python
agent = create_agent(
    model=get_llm(),              # DeepSeek V4
    tools=[crawl_webpage, ...],   # 18 个工具
    system_prompt=SYSTEM_PROMPT,  # 纯静态（缓存关键）
    checkpointer=checkpointer,    # SqliteSaver 会话持久化
    middleware=[trim_middleware, script_forcer],  # 双中间件
)

# 暴露给 server.py：每轮对话开始时重置失败计数（防跨轮累积误触发）
agent._script_forcer = script_forcer

# 双模式流式调用
for mode, event in agent.stream(
    {"messages": [HumanMessage(content=user_input)]},
    config={"configurable": {"thread_id": session_id}},
    stream_mode=["messages", "values"],
):
    ...
```

- `stream_mode=["messages", "values"]`：
  - `messages` → token 级增量（`ai_delta` 逐字上屏）
  - `values` → 完整状态快照（工具调用/结果/指标）

## 完整请求数据流（8 步）

| # | 步骤 | 细节 |
|---|------|------|
| 1 | 用户发消息 | WebSocket `/ws/{session_id}` 或终端输入；HumanMessage 追加到 state |
| 2 | `agent.stream()` | create_agent 收到消息，调 DeepSeek API（命中 prompt cache） |
| 3 | LLM 返回 tool_calls | 如 `crawl_webpage(url='https://...')` |
| 4 | 工具执行 | `@tool` 函数运行（requests/Playwright/BS4），结果以字符串返回 |
| 5 | 置信度检查 | score < 60 → 结果尾部追加 `[LOW CONFIDENCE]` 标记 |
| 6 | LLM 处理结果 | 看到低置信标记 → 自动调 `browse_and_crawl` 重抓；否则决定继续调工具或回复 |
| 7 | 最终 AI 回复 | token 级流式推送（`ai_delta`），SessionMetrics 记录计时与 token |
| 8 | 状态持久化 | SqliteSaver 保存完整消息历史，下次输入自动恢复上下文 |

## 置信度评分与自动升级（`tools/confidence.py`）

**设计动机**：静态 HTTP 抓取拿到的可能是 SPA 空壳、反爬页、字体加密乱码。用规则启发式打分（毫秒级、零 LLM 成本）判断提取质量，低分自动升级 Playwright 浏览器重抓。

```
crawl_webpage() ──> extract_content() ──> score >= 60？──是──> 保存 & 回复
 (HTTP 快)           (BS4 解析+评分)          │
                                          否
                                           ▼
                              browse_and_crawl() ──> extract_content() 重试
                              (Playwright JS 渲染)
```

### 评分规则（基准 100 分）

| 检查项 | 扣/加分 |
|--------|---------|
| 内容为空 | -50 |
| 内容 < 200 字 | -30 |
| PUA 乱码 > 10%（字体加密） | -60 |
| PUA 乱码 > 5% | -40 |
| 反爬标记（403/forbidden/登录/验证码） | -50 |
| JS 占位（loading/请启用 JavaScript） | -40 |
| 句子数 < 3 | -20 |
| 语言占比异常 | -20 |
| 内容 > 500 字 | +10 |
| 中文占比 > 30% | +10 |
| 句子数 > 10 | +10 |

**触发条件**：`should_upgrade = score < 60`

### 升级链路

1. `extract_content()` 内部调 `evaluate_confidence(content, title, url)`
2. 低分 → 工具返回值末尾追加 `[LOW CONFIDENCE: score=N, reasons=...]`
3. SYSTEM_PROMPT 中有硬规则：「看到 `[LOW CONFIDENCE]` 标记，立即用相同 URL 调 `browse_and_crawl`，然后对返回的 HTML 重新 `extract_content`」
4. 浏览器渲染后重新提取，分数应 ≥ 60

## 会话持久化（checkpointer）

- `SqliteSaver`（SQLite）按 `thread_id` = `session_id` 存**完整**消息历史（append-only）
- 进程重启后 WebUI 重连会自动恢复会话上下文，无需向量库
- 所有会话共享 `data/sessions.db`——新标签页打开历史会话即可续接
- 删除会话时先归档完整消息到 `logs/{session_id}_{时间戳}.json`，再清 checkpoints/writes 两表

## Token 膨胀治理（`graph/middleware.py`）

**矛盾**：checkpointer 持久化完整历史（保证 DeepSeek 缓存前缀稳定），但传给 LLM 的 messages 不能无限膨胀，否则几轮就 API 超时。

**解法**：`TrimHistoryMiddleware` 用 `wrap_model_call` 拦截 model 调用，**只改传给 LLM 的输入，不改持久化 state**。

裁剪策略（两层）：
1. **工具结果裁剪**：超长 ToolMessage 截断为首尾 `tool_result_max_chars`（2000，保留首尾，中间省略）
2. **半水位淘汰**：总 token 超 `history_max_tokens`（32000）时，**一次性**淘汰到半水位（max/2），此后窗口固定、消息只追加 → 缓存前缀稳定。`history_keep_recent_turns`（3）是下限：淘汰起点不得晚于倒数第 3 轮，若 3 轮本身已超半水位则宁超预算也不再砍

> 为什么不再用「滑动窗口」：固定保留最近 N 轮会让窗口起点每轮都移动，历史前缀永远无法命中缓存（实测命中率仅 37.5%，命中的只有 system prompt + 工具定义）。改成半水位淘汰后，起点固定不动，命中率随对话持续上升。

约束：ToolMessage 必须与其配对的 AIMessage.tool_calls 一起保留，否则 OpenAI API 报 `tool_call_id` 不匹配错误。

## 防死循环治理（`graph/script_forcer.py`）

**解决的问题**：Agent 曾出现连调 72 次工具仍不换策略的死循环——"换一个内置工具 → 失败 → 再换一个"，永远不会用 `run_custom_script`。

**解法**：`ScriptForcerMiddleware` 在 `wrap_tool_call` 里判定每次工具结果成败并计数，在 `wrap_model_call` 里按阈值注入 SystemMessage 强制改道。

```
工具结果判定：
  失败 = 空/<50字符/匹配 ERROR|FAILED|LOW CONFIDENCE|SPA shell|anti-crawl|timeout 等 16 种模式
  成功 = SAVED:|FOUND:|NO_PROFILE:|JSON 开头|CONFIDENCE:

触发链（agent.py 装配参数）：
  连续失败 ≥3 次 → 注入"必须用 run_custom_script"指令
  连续失败 ≥5 次 → 最强指令：禁止调用任何内置工具
  单轮总调用 ≥30 次 → TASK FORCE-FINISH：强制停止调工具、立即总结
  连续同工具 ≥5 次 → 注入"你在死循环，必须换策略"
```

要点：
- `run_custom_script` 自身的失败不计入计数（允许脚本重试换思路），但会清零强制标志
- 计数状态在每轮对话开始时由 server.py 调 `_script_forcer._reset()` 清零，防跨轮累积误触发

## 事件日志与断线重放（`web/server.py`）

**解决的问题**：旧方案把流式事件直接塞 `asyncio.Queue` 单消费者——页面刷新时旧消费者已死但仍"吞"事件，新订阅者收不到 `done`，前端永远转圈"思考中"。

**解法**：每轮任务的全部事件同时 append 到内存事件日志（`_active_turns[session]["events"]`），订阅协程按 cursor 增量发送：

```
worker 线程 _run_turn ──┬──> events.append(event)   # 事件日志（真相源）
                        └──> queue.put(event)        # 仅作唤醒通知

订阅协程 _stream_turn ──> 从 cursor=0 重放日志 → 追平后等 queue 唤醒 → 继续发
```

- 重连（页面刷新）：新 WS 订阅从 cursor=0 全量重放，不丢任何事件
- 同会话多订阅者：`ws_id` 标记最新订阅者，旧订阅协程自动退出
- 任务已结束时重连：直接补发一条 `done` 让前端结束 busy 状态

## Prompt Caching 策略（`llm/model.py`）

DeepSeek 服务端自动缓存请求的最长公共前缀。为保证命中率：

1. SYSTEM_PROMPT 纯静态字符串（无时间戳/随机数）
2. 工具定义（docstring）稳定，不运行时修改
3. 消息顺序固定：system prompt → tool definitions → history
4. 历史只追加不修改（append-only）

## 思考模式（thinking_depth）

| 值 | 行为 |
|----|------|
| `off` | `extra_body={"thinking": {"type": "disabled"}}` + `temperature=0` |
| `low` / `high` / `max` | `thinking: enabled` + `reasoning_effort`，不传采样参数 |
| `medium` | 映射为 `high`（DeepSeek 仅 3 档） |

推理内容从 `AIMessage.additional_kwargs.reasoning_content` 提取，经 `ai_thinking` 事件推给前端折叠展示。
