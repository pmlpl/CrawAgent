# 05 · 扩展指南

## 一、添加新工具（最常见扩展）

### 第 1 步：创建工具文件

```python
# crawagent/tools/my_tool.py
"""My custom tool description."""
from langchain_core.tools import tool

@tool
def my_tool(param1: str, param2: int = 10) -> str:
    """Tool description for LLM.

    The docstring IS the tool spec that LLM sees.
    Be precise — this is how the model decides when
    to call your tool.

    Args:
        param1: Description of param1
        param2: Description of param2 (default 10)
    """
    # Your implementation here
    result = f"Processed {param1} with {param2}"
    return result
```

### 第 2 步：注册到 agent.py

```python
# crawagent/graph/agent.py

# 1. 导入
from crawagent.tools.my_tool import my_tool

# 2. 加入 tools 列表
tools = [
    crawl_webpage,
    browse_and_crawl,
    # ... 现有工具 ...
    my_tool,  # <-- 加在这里
]

# 3. 在 SYSTEM_PROMPT 的 capabilities 段加一行：
#    17. my_tool(param1, param2) — One line description of when to use it
```

### 第 3 步：验证

```bash
# 导入检查
python -c "from crawagent.tools.my_tool import my_tool; print(my_tool)"

# 冒烟测试（可选，建议加到 tests/test_smoke.py）
def test_my_tool():
    from crawagent.tools.my_tool import my_tool
    assert callable(my_tool)
```

### 关键规则

- **docstring 就是 LLM 的说明书**——写清楚何时用、怎么传参，模型完全靠它决策
- **类型注解必须有**——LLM 用它构造参数（str, int, bool, list[str] 等）
- **返回值必须是 str**——LangChain 把它转成 ToolMessage 内容
- 需要新依赖（Playwright/fonttools 等）→ 加到 `pyproject.toml` 的 `[project.optional-dependencies]`

## 二、添加新站点类型工具

以 Amazon 商品页为例：

1. 新建 `crawagent/tools/amazon_tool.py`
2. 处理站点特有反爬逻辑（在工具内部封装，别暴露给 LLM）
3. 复用 `crawl_webpage` / `browse_and_crawl` 作为抓取基础
4. 用 `confidence.py` 的 `evaluate_confidence` 打分，低分自动升级
5. 注册 agent.py + 更新 SYSTEM_PROMPT 工作流
6. 成功后用 `save_site_profile` 保存策略

## 三、添加自定义中间件

用途：限流、内容过滤、注入防御、A/B 测试等横切关注点。

```python
# crawagent/graph/middleware.py 中新增

from langchain.agents.middleware import AgentMiddleware

class MyMiddleware(AgentMiddleware):
    def wrap_model_call(self, request, handler):
        # request.messages: 即将传给 LLM 的消息（可修改）
        # 例：过滤/增强/注入消息
        return handler(request)  # 继续执行
```

然后在 `agent.py` 的 `create_agent(middleware=[...])` 中注册。

参考实现：`TrimHistoryMiddleware`（滑动窗口 + 工具结果裁剪，只改 LLM 输入不污染持久化 state）。

## 四、添加 REST API 端点

```python
# crawagent/web/server.py

@app.get("/api/export/{session_id}")
async def export_session(session_id: str) -> dict:
    """导出会话为 markdown"""
    def _load():
        agent = _get_agent()  # 复用单例
        state = agent.get_state({"configurable": {"thread_id": session_id}})
        # ... 拼装 markdown ...
        return {"markdown": "..."}
    return await asyncio.to_thread(_load)  # 避免阻塞事件循环
```

要点：
- DB/Agent 操作包在 `asyncio.to_thread()` 里
- 复用 `_get_agent()` / `_get_checkpointer()` 单例
- 前端：在对应 Vue 组件加按钮调这个接口

## 五、切换 LLM 提供商

```python
# crawagent/llm/model.py — get_llm()

# 换成任何 LangChain chat model：
from langchain_anthropic import ChatAnthropic     # Claude
from langchain_google_genai import ChatGoogleGenerativeAI  # Gemini
from langchain_ollama import ChatOllama           # 本地模型

def get_llm():
    return ChatAnthropic(model="claude-sonnet-4-5", api_key=...)
```

注意：
- prompt cache 是 DeepSeek 特性，其他提供商缓存机制不同
- System Prompt 保持静态在任何提供商下都是最佳实践
- 工具调用（tool calling）能力是硬要求，选模型时必须支持

## 六、WebUI 事件协议（改前端必读）

### WebSocket `/ws/{session_id}`

客户端 → 服务端：

```json
{"type": "message", "content": "用户文本"}
{"type": "stop"}
```

服务端 → 客户端：

| 事件 | 字段 | 前端组件 |
|------|------|---------|
| `tool_call` | name, args, tool_call_id | CrawlTrace.vue（折叠轨迹） |
| `tool_result` | tool_call_id, content | CrawlTrace.vue（结果预览，截断 600 字） |
| `ai_thinking` | id, content | Thinking.vue（推理内容，折叠） |
| `ai_delta` | id, delta | token 级流式逐字上屏 |
| `ai_done` | id | 关闭流式光标 |
| `ai` | content | 非流式兜底（整段文本） |
| `status` | line | 状态栏（常驻输入框下方） |
| `resumed` | — | 重连时任务仍在运行 → 前端恢复 busy/停止按钮 |
| `done` | — | 本轮结束 |
| `error` | message | 本轮失败 |

### REST 端点一览

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/` | Vue index.html |
| GET | `/assets/*` | 静态 JS/CSS |
| GET | `/api/sessions` | 会话列表（含预览，最多 50 条） |
| DELETE | `/api/sessions/{id}` | 删除会话（先归档 JSON 到 logs/） |
| POST | `/api/sessions/bulk-delete` | 批量删除，body `{"ids": [...]}`；自动跳过运行中会话 |
| GET | `/api/history/{id}` | 历史消息 + 状态栏 |
| GET | `/api/settings` | 模型注册表 + 思考深度（Key 不出后端，只返回 key_set） |
| POST | `/api/settings` | 保存思考深度到 .env |
| POST | `/api/models` | 添加模型（服务商/模型 ID/API Key/Base URL） |
| POST | `/api/models/update` | 编辑模型（Key 留空 = 保留原 Key） |
| POST | `/api/models/delete` | 删除模型 |
| POST | `/api/settings/test` | 测试 API 连通性（Key 留空按服务商取已存 Key） |
| GET | `/api/sites` | 站点档案列表 |
| POST | `/api/sites` | 新建/更新站点档案（可带 cookies/script） |
| DELETE | `/api/sites/{origin}` | 删除站点档案 |

### 服务端关键机制

- **Agent 惰性初始化**：无 API Key 时服务能起，会话列表也能看，首次对话才报错
- **会话锁**：`_session_locks` 保证同会话同时只有一个活跃 turn
- **事件日志重放**：轮次事件 append 到 `_active_turns[session]["events"]`，WS 重连从 cursor=0 全量重放，`done`/`error` 永不丢失（详见 03-核心机制）
- **停止**：`cancelled` 标志位，当前工具调用完成后生效
- **批量删除**：跳过 `_active_turns` 中的运行中会话，返回 `skipped_active` 数量
- **每轮重置 ScriptForcer**：`_run_turn` 开头调 `agent._script_forcer._reset()` 清空失败计数
